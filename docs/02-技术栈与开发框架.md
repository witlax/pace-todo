## 3. 开发框架

### 3.1 分层

```
表现层 presentation  ── Widget / Page / Controller(Notifier)
        │  只依赖 domain 的接口与实体，不直接写 SQL
应用层 application   ── 用例（创建任务、完成习惯、开始专注）
        │  编排仓储与平台服务，处理事务边界
领域层 domain        ── 实体 / 值对象 / 仓储接口 / 纯函数（streak、RRULE 展开、优先级算法）
        │  零 Flutter 依赖，可纯 Dart 单测
数据层 data          ── Drift DAO / 仓储实现 / 平台适配（通知、托盘、小组件）
```

规则：**依赖只能向下**（presentation → application → domain ← data）。`domain` 与 `application` 层禁止 import Flutter，也禁止 import `dart:io`——这是为将来"手机作局域网后端、电脑浏览器访问"预留的前提（ADR-0009）。

### 3.2 目录结构

```
app/
├─ lib/
│  ├─ main.dart
│  ├─ app/                 # 入口、路由表、主题、本地化、启动引导
│  │  ├─ router.dart
│  │  ├─ theme.dart
│  │  └─ bootstrap.dart
│  ├─ core/                # 跨域基础设施
│  │  ├─ db/               # Drift 数据库、表定义、迁移、DAO 基类
│  │  ├─ time/             # 时钟抽象、时区、日期工具（可注入，便于测试）
│  │  ├─ logging/          # 日志与操作审计
│  │  ├─ errors/           # 失败类型、Result
│  │  └─ utils/
│  ├─ features/
│  │  ├─ tasks/            # data / domain / application / presentation
│  │  ├─ lists/
│  │  ├─ calendar/
│  │  ├─ focus/
│  │  ├─ habits/
│  │  ├─ stats/
│  │  └─ settings/
│  ├─ platform/            # 平台能力适配（notifications / widget / tray / shortcuts）
│  └─ shared/              # 通用 Widget、设计令牌
├─ test/                   # 与 lib 同构的测试目录
├─ integration_test/
├─ android/  windows/
└─ docs/                   # 项目内文档（与根 docs 区分：根目录放全局）
```

### 3.3 关键抽象（必须在 M0 落地）

| 抽象 | 作用 | 为什么必须有 |
| --- | --- | --- |
| `Clock` | 注入"现在" | streak、逾期、提醒的测试必须可控制时间 |
| `TaskRepository` | 领域接口 | 隔离 Drift，未来换同步实现不动 UI |
| `ReminderScheduler` | 平台无关的排程接口 | Android 精确闹钟与 Windows Toast 差异在此收敛 |
| `RecurrenceService` | RRULE 展开 + 例外日 | 重复规则是最易出错的纯逻辑，必须独立可测 |
| `AuditLog` | 记录用户关键操作 | 出问题时能回答"这条任务什么时候被谁改的" |
| `ViewRegistry` | 视图注册表：可用性、手机可见性、最小宽度、依赖字段 | 视图按设备裁剪，新增视图不改导航（ADR-0010） |
| `NoteRepository` | 备忘录读写 + 关联 | 备忘录是一等实体，不与任务备注混用（ADR-0011） |

### 3.4 平台差异矩阵

| 能力 | Android | Windows | 统一策略 |
| --- | --- | --- | --- |
| 主布局 | 底部 4 Tab + 抽屉 | 三栏（导航/列表/详情） | 断点 <600 / 600–1000 / >1000 切换 |
| 任务详情 | 全屏页面 | 右侧面板 | 同一 Widget，容器不同 |
| 提醒 | AlarmManager + 通知动作 | Toast（不支持重复） | 排程层按平台降级，UI 文案区分"精确/大约" |
| 番茄计时 | 前台服务 | 前台定时器 + 托盘 | `FocusRuntime` 抽象 |
| 快速捕获 | 分享接收 + 小组件 | 全局快捷键 + 托盘 | 各自入口，同一用例 |
| 最小化 | 后台 | 托盘常驻 | 平台判断 |

### 3.6 编码规范

- `dart format`（行宽 100）+ `flutter analyze` 零告警，作为提交门槛。
- 命名：文件 `snake_case.dart`，类 `UpperCamelCase`，Provider 后缀 `Provider`，Notifier 后缀 `Notifier`。
- 禁止在 Widget 内直接 `DateTime.now()`，一律用 `Clock`。
- 禁止在 UI 层拼 SQL；查询只能出现在 DAO/Repository。
- 所有用户可见文案走 ARB（zh/en），不写硬编码中文。
- 单文件超过 300 行需拆分；单函数超过 50 行需拆分。
- 注释只写"为什么"，不写"是什么"；复杂规则（RRULE、streak）必须有文档注释 + 单测。

### 3.7 设计令牌与断点

| 断点 | 布局 |
| --- | --- |
| < 600 dp | 单列 + 底部 4 Tab + FAB |
| 600–1000 dp | 双栏（列表 + 详情），Tab 仍在底部 |
| ≥ 1000 dp | 三栏（导航 / 列表 / 详情），可选并排副视图 |

重要性色板（唯一语义，见 ADR-0012）：

| Token | 浅色主色 | 浅色底 | 深色主色 | 色觉友好 |
| --- | --- | --- | --- | --- |
| `importanceHigh` | `#C2333A` | `#FCEBEB` | `#F09595` | `#A21CAF` |
| `importanceMedium` | `#B45309` | `#FAEEDA` | `#EF9F27` | `#B45309` |
| `importanceLow` | `#185FA5` | `#E6F1FB` | `#85B7EB` | `#0F6E56` |
| `importanceNone` | `#6B7280` | `#F3F4F6` | `#9CA3AF` | `#6B7280` |

其它基础令牌：圆角 `card 12 / sheet 16 / button 10`；触控最小 `48 dp`；列表行高 `56 dp`；正文 `15–16 sp`、次要 `13 sp`。

### 3.8 质量门禁（Definition of Done）

一个改动只有全部满足才算完成：

1. `dart format .` 无 diff
2. `flutter analyze` 0 issues
3. `flutter test` 全绿（新增逻辑必须有测试）
4. `flutter build apk --debug` 与 `flutter build windows --debug` 均成功
5. `DEVLOG.md` 有本次操作记录
6. 提交信息符合 Conventional Commits
7. 涉及决策的，补 ADR
