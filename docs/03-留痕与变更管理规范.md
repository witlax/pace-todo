# 开发留痕与变更管理规范

> 目标：任何一行代码、任何一次环境改动，都能回答三个问题——**什么时候改的、改了什么、为什么改**。
> 状态：自 2026-11-18 起生效，对项目全部操作强制适用。

---

## 1. 四层留痕模型

单一日志不够可靠，因此分四层，各管一件事，互相印证。

| 层 | 载体 | 记录什么 | 谁写入 | 可否修改 |
| --- | --- | --- | --- | --- |
| L1 时间线 | `DEVLOG.md` | 每一次操作：环境变更、依赖升级、结构改动、构建结果、踩坑与结论 | 人 / Agent，用 `scripts/devlog.sh` | **只追加，不修改** |
| L2 决策 | `docs/adr/NNNN-*.md` | 为什么这样选，放弃了什么，什么条件下要重新评估 | 人 / Agent | 不可改；推翻需新增 ADR |
| L3 代码事实 | Git 提交 | 代码与文档的确切差异、作者、时间 | Git 钩子自动校验 | 不重写历史 |
| L4 版本 | `CHANGELOG.md` | 面向使用者的功能与修复清单 | 发布时汇总 | 只追加新版本段 |

补充：`.workbuddy/memory/YYYY-MM-DD.md` 记录跨会话的工作记忆，属于 Agent 的个人笔记，不作为审计依据。

---

## 2. 什么操作必须留痕

| 类别 | 判定 | 记录位置 | 必填内容 |
| --- | --- | --- | --- |
| **ENV** 环境变更 | 安装/升级 SDK、JDK、Flutter、修改 PATH、改系统配置 | DEVLOG | 原状态、新状态、命令、原因、验证方式 |
| **DEP** 依赖变更 | 增删改 `pubspec.yaml`、Gradle 依赖、镜像源 | DEVLOG + ADR（若替换选型） | 包名、版本、用途、体积/权限影响 |
| **SCHEMA** 数据模型变更 | 新增表/字段、改索引、写迁移 | DEVLOG + ADR（若破坏兼容） | 迁移版本号、旧数据如何转换、回滚方案 |
| **STRUCT** 结构调整 | 目录重组、分层变更、公共抽象增删 | DEVLOG + ADR | 影响范围 |
| **FEAT / FIX** 功能与修复 | 任何用户可见变化 | DEVLOG + Git + CHANGELOG | 行为变化、验证方式 |
| **BUILD** 构建与发布 | 构建失败与修复、签名、打包 | DEVLOG | 报错原文、根因、解法 |
| **DOC** 文档 | 规范、PRD、评估 | DEVLOG（一句话） | — |
| **DECISION** 决策 | 技术选型、范围裁剪、优先级调整 | ADR + DEVLOG 摘要 | 备选项、取舍理由、重评估条件 |

不要求留痕的：临时试验（但结论要留）、纯格式化的编辑器操作、`dart format` 自动改动。

## 3. DEVLOG 格式

文件为一张表，**只允许在文件末尾追加行**，不允许改写历史行。

```markdown
| 时间 | 类型 | 内容 | 提交 |
| --- | --- | --- | --- |
| 2026-11-18 23:12 | ENV | 环境基线检查：Flutter 3.47.7 / Dart 3.13.5 / JDK 17 均达标 | - |
```

- 时间：`YYYY-MM-DD HH:mm`，本地时间。
- 类型：上表英文标签，固定枚举。
- 内容：一句话说清 **做了什么 + 结果**；失败必须写**报错关键行**与**下一步**。
- 提交：短哈希，未提交填 `-`。

写入方式（统一入口，避免格式漂移）：

```bash
./scripts/devlog.sh ENV "安装 Android SDK 36.0.0，原为 35.0.0；命令 sdkmanager ...；验证 flutter doctor Android 通过"
```

## 4. Git 约定

### 4.1 提交信息（Conventional Commits）

```
<type>(<scope>): <subject>

<body: 为什么改，改了什么，验证方式>
```

`type` 枚举：`feat` `fix` `refactor` `perf` `docs` `test` `build` `ci` `chore` `revert`
`scope` 示例：`tasks` `calendar` `focus` `habits` `db` `android` `windows` `deps` `env`

示例：

```
feat(tasks): 支持按清单与标签组合筛选

智能清单需要复用同一套筛选 DSL。新增 TaskFilter 值对象，
将查询条件编译为 Drift 表达式，避免各视图重复写 WHERE。

验证：新增 6 个单测覆盖空条件/多条件/日期边界；analyze 0 issue。
DEVLOG: 2026-11-19 10:20 FEAT
```

### 4.2 钩子（由 `scripts/setup-hooks.sh` 安装）

| 钩子 | 作用 |
| --- | --- |
| `commit-msg` | 校验提交信息符合 Conventional Commits，不符合直接拒绝 |
| `pre-commit` | 若改动涉及 `pubspec.yaml`、`android/`、`lib/core/db/`、`docs/adr/`，则必须同时暂存 `DEVLOG.md`，否则拒绝提交 |

> `--no-verify` 跳过钩子属于违规操作。确需跳过（如紧急回滚），必须在 DEVLOG 中写明原因与影响。

### 4.3 分支与提交粒度

- 主干 `main` 始终可构建；功能分支 `feat/xxx`、修复分支 `fix/xxx`。
- 一次提交只做一件事；不允许"顺手重构"混在功能提交里。
- 合并前必须通过质量门禁（`docs/02` 第 3.7 节）。

## 5. ADR 规范

- 位置：`docs/adr/NNNN-kebab-title.md`，四位递增编号，不复用。
- 结构固定：`状态 / 背景 / 决策 / 备选方案 / 后果 / 重新评估条件`。
- 状态：`提议` → `已接受` → `已废弃（被 NNNN 取代）`。

## 6. 审计方法

| 想知道 | 查哪里 |
| --- | --- |
| 某依赖何时引入、为什么 | `git log -S "package_name" -- pubspec.yaml` → 对应 DEVLOG 行 → 若有选型替换看 ADR |
| 某表字段为何这样设计 | `docs/adr/` + `lib/core/db/` 的迁移文件注释 |
| 某次构建为什么失败过 | `grep BUILD DEVLOG.md` |
| 某功能何时上线 | `CHANGELOG.md` + `git tag` |
| 谁在什么时候改了这一行 | `git blame` |

**自检频率**：每个里程碑结束时执行一次 `git log --oneline` 与 DEVLOG 行数比对，缺漏补记并说明。

---

## 7. 禁止事项

1. 批量改写或删除 `DEVLOG.md` 历史行。
2. 修改已接受的 ADR 结论（应新增取代 ADR）。
3. 直接改数据库 schema 而不写迁移与 DEVLOG。
4. 用 `--no-verify` 且不留说明。
5. 在提交里混入无关改动。
6. 把密钥、Token、个人隐私数据写入任何留痕文件。
