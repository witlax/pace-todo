# 任务待办工具 —— 调研与技术评估

> 目标：以 `pinch`（片趣打卡）与 `siyuan-plugin-task-horizon`（任务管理器）为功能参考，结合滴答清单的产品形态，设计一款 **Android 优先、同步支持 Windows** 的个人效率工具。
> 本文只做调研与评估，不进入编码。数据截至 2026-11-18。

---

## 0. 结论摘要

| 结论 | 内容 |
| --- | --- |
| 产品定位 | 不做"又一个滴答清单"，做 **离线优先 + 隐私本地 + 任务/专注/打卡闭环** 的个人工具 |
| 技术栈 | **Flutter 3.x + Riverpod + Drift(SQLite) + go_router**，一套代码覆盖 Android 与 Windows |
| 为什么不是 RN/KMP | RN 的 Windows 桌面是社区方案且 Expo 不支持；KMP 的 Windows 需另一套 UI，人力近乎翻倍 |
| 复用策略 | 不 fork 任何现有 App，借鉴 4 个项目的架构与交互；数据库/同步层自研 |
| 开源空白 | GitHub 上**没有**同时覆盖「任务 + 番茄 + 打卡 + Android/Windows + 同步」的成熟开源项目，必须自研壳 |
| V1 范围 | 任务 + 智能清单 + 提醒 + 重复 + 日历(月/周) + 番茄 + 打卡 + 基础统计 + 本地备份 |
| 工作量 | MVP 约 **55～65 人日**；完整 V1.0 约 **110～130 人日**（单人 + AI 辅助） |
| 最大风险 | Android 后台保活与精确闹钟（国内 OEM）、重复任务提醒重排、跨端同步冲突 |

## 1. 两个思源插件的功能拆解

### 1.1 Pinch（片趣打卡）v2.8.0

- 仓库：`royc01/pinch`，MIT，TypeScript + Vue 3 + Vite
- 规模：`src/` 约 366 个文件，75 个 Vue 组件，60 个 composable，**大量 vitest 单测**（工程完成度高）
- 数据层：任务来自思源任务块 + `custom-task-*` 属性，通过 SQL 查询聚合；另有 **CRDT 层**（`crdt.ts` / `crdtStore.ts`）做字段级多端合并
- 移动端：独立的移动任务创建弹窗、移动端布局适配

| 模块 | 关键能力 | 可借鉴点 |
| --- | --- | --- |
| 习惯打卡 | 习惯难度、频率（每日/每周/自定义/每周 N 次）、完成模式（次数/时长）、补卡、打卡备注、连续天数、热力图 | **频率模型**与 **streak 计算**是最完整的参考 |
| 番茄钟 | 自定义时长、正计时、白噪音（5 个 ogg 场景）、悬浮胶囊窗、微休息提醒、习惯绑定番茄 | 悬浮窗 + 白噪音 + 习惯联动 |
| 心情打卡 | 每日情绪记录、趋势图、心情日历 | 低成本高情感价值，适合做差异化 |
| 目标系统 | 子目标、四种进度方式（任务/手动/专注/习惯）、暂停、补录、归档 | **目标作为聚合层**，把任务/习惯/专注串起来 |
| 奖励系统 | 打卡与完成任务得币、兑换商店 | 滴答清单没有，天然差异化 |
| 任务管理 | 清单/表格/看板/日历/甘特、标签、自定义状态与颜色、提醒、文档内徽章 | 徽章式行内编辑体验 |
| 统计复盘 | 个人工作台、可拖拽统计卡片、摘要导出图片 | "可组装的统计卡片" |
| 同步 | CalDAV 单向同步（VEVENT/VTODO）、云备份 | VTODO 映射经验 |

**短板**：强依赖思源块数据模型，离开思源即不可用；番茄与任务耦合较浅；无独立同步服务。

### 1.2 Task Horizon（任务管理器）v3.4.9

- 仓库：`5kyfkr/siyuan-plugin-task-horizon`，TypeScript，FullCalendar + 自研视图
- 规模：`src/` 90 个文件，含 30+ 份设计与性能文档（`docs/PRD.md` 即一份高质量 PRD）
- 数据层：思源任务块为唯一数据源，字段存于块属性，插件存储保存视图/配置

| 模块 | 关键能力 | 可借鉴点 |
| --- | --- | --- |
| 任务聚合 | 全部文档 / 笔记本 / 自定义文档分组，支持子文档、隐藏页签 | **文档分组 + 规则**替代传统"清单" |
| 六视图 | 清单、表格、时间轴(Gantt)、看板、日历、白板 | 视图可开关，不默认全塞 |
| 主页仪表盘 | 完成率、趋势、热力图、文档分布、最近完成、逾期风险 | 复盘页的信息结构 |
| 任务字段 | 重要性、自定义状态、开始/截止、预计时长、已耗时、备注、附件、循环、提醒、自定义字段、里程碑、置顶 | **字段化任务模型**是全部视图的地基 |
| 排序算法 | 自定义权重 + 规则 + 文档加减分的**加权优先级** | 比单一优先级更贴近真实决策 |
| 四象限 | 按重要性与时间范围自定义分组规则与颜色 | 规则化四象限，而非硬编码 |
| quickbar | 文档内任务块悬浮编辑条 + 行尾常驻字段 | 极低摩擦的行内编辑 |
| 日历 | 月/周/日/三日、日程与任务双轨、拖拽、节假日与农历、番茄联动 | **任务与日程双轨**是日历的正确抽象 |
| AI | MiniMax / DeepSeek，任务快照、字段 patch、自然语言排期 | AI 作为可选层，可完全隐藏 |
| 导入导出 | 滴答清单 CSV 导入、Excel/Markdown 导出 | 迁移路径设计 |

**短板**：仅在思源内运行；移动端是"能用"而非"原生"；白板/多视图维护成本极高。

### 1.3 合并后的能力清单（去重）

```
任务域：清单/分组 · 标签 · 子任务 · 优先级 · 自定义状态 · 开始/截止 · 预计/实际时长
        · 备注(Markdown) · 附件 · 重复规则 · 提醒 · 置顶 · 里程碑 · 自定义字段
时间域：日历(月/周/日) · 时间轴 · 智能清单(今天/最近7天/逾期) · 日程与任务双轨
执行域：番茄钟 · 正计时 · 白噪音 · 悬浮窗 · 微休息 · 任务耗时回写
习惯域：习惯定义 · 频率 · 打卡 · 补卡 · streak · 热力图 · 心情
复盘域：完成率 · 趋势 · 热力图 · 分布 · 逾期风险 · 目标进度 · 奖励
系统域：多端同步 · 提醒可靠性 · 主题 · i18n · 备份 · 导入导出
```

### 1.4 两个插件暴露出的共同工程教训

1. **单一数据源 + 乐观更新 + 局部刷新**：Task Horizon 的 PRD 反复强调"修改后不得整页闪烁"，说明这是最容易翻车的地方。
2. **性能必须前置设计**：两者都有缓存、批量查询、虚拟列表、增量刷新的专门文档。任务量过千后，全量重绘必崩。
3. **移动端不是缩小版桌面**：入口、详情（底部抽屉 vs 右侧栏）、长按/短按语义都要单独设计。
4. **字段化模型的价值**：一旦任务被结构化，视图、筛选、统计、AI 全是"查询的不同投影"，新增视图成本极低。
5. **提醒与重复是最脏的模块**：两者都为此写了大量测试与边界处理（跨时区、跳过、补卡、重排）。

## 2. 滴答清单的功能与布局拆解

### 2.1 信息架构

```
┌ 侧边栏（抽屉） ────────────────────────┐
│ 头像 / 设置                            │
│ 智能清单：今天 · 明天 · 最近7天 ·       │
│          收集箱 · 指派给我 · 所有 ·     │
│          已完成 · 垃圾桶                │
│ 清单 + 文件夹（可置顶、Emoji 图标、背景）│
│ 标签                                   │
│ 过滤器（自定义条件保存为视图）           │
│ 日历订阅                               │
└───────────────────────────────────────┘
底部 Tab：任务 · 日历 · 专注 · 习惯   （可在设置中增减）
            └ 长按 Tab 快速切换智能清单 / 日历视图
右下 FAB：新建任务（长按语音输入）
任务详情：移动端全屏；桌面端三栏（清单 - 任务 - 详情）
```

**关键设计**：底部只有 4 个"域级"入口，清单与标签全部收进侧边栏。这样主界面永远是"当前上下文的任务流"，而不是功能菜单。

### 2.2 五个一等公民

| 域 | 核心界面 | 关键交互 |
| --- | --- | --- |
| 任务 | 列表（分组 + 折叠）、看板、时间线、四象限 | 左滑完成/延期/专注（动作可配置）、点击进详情、长按多选 |
| 日历 | 年/月/周/日/日程/多日/多周 | 拖拽改期、长按 1 秒新建、全天区折叠汇总 |
| 专注 | 番茄 / 正计时、常用专注 | 从任务左滑或详情启动、白噪音、专注笔记、结束后可补时/修正 |
| 习惯 | 习惯列表 + 月历 + 统计 | 一键打卡、目标次数、备注、连续天数、月度完成率 |
| 统计 | 任务完成 / 专注时长 / 习惯记录 | 周报、趋势、环形图 |

### 2.3 任务字段模型（事实标准）

`标题` · `描述(Markdown/图片/录音)` · `子任务` · `开始时间` · `截止时间` · `全天` · `提醒(多个/持续/位置)` · `重复规则` · `优先级(高/中/低/无)` · `清单` · `标签` · `附件` · `评论` · `完成时间`

> 这套字段是十余年迭代出来的最小完备集。**V1 不要自创字段命名**，直接对齐，后续迁移与用户认知成本最低。

### 2.4 值得直接抄的 12 个交互细节

1. 智能清单支持「显示 / 隐藏 / **有内容时显示**」三态。
2. 长按底部 Tab 切换到该域的次级视图，再点回到顶部。
3. 任务左滑动作可配置（完成 / 延期 / 专注 / 删除）。
4. 快速添加时 NLP 解析"明天下午三点开会"。
5. 提醒通知上直接提供「完成 / 稍后提醒」按钮。
6. 日历长按 1 秒新建，拖拽即改期，松手即保存。
7. 详情页字段做成一行 chip，点开即改，不跳二级页。
8. 子任务内联新增，回车连续添加。
9. 完成任务的微动效 + 声音（正反馈，成本极低）。
10. 空态给引导动作，不给空白页。
11. 专注结束允许"补时"与"修正时长"（真实使用必然发生）。
12. 周报/复盘卡片可导出图片（社交传播点）。

### 2.5 免费与付费的边界（决定我们的取舍）

滴答清单的付费点集中在：日历视图与月视图、更多清单数、自定义过滤器、部分主题、协作。**任务核心、提醒、番茄、习惯的基础形态是免费的。**

对我们的启示：个人自用工具不需要设计付费墙，但**必须砍掉协作、共享、日历订阅、多主题**这些高成本低收益模块。

### 3.1 直接相关项目（星数为 2026-11-18 实测）

| 项目 | 星 | 语言 | 平台 | 许可 | 可借鉴 | 不能直接用的原因 |

| `super-productivity/super-productivity` | 23.8k | TS/Angular | Web/Electron/移动壳 | MIT | 时间盒、计时、看板、四象限、Jira/GitHub 集成、多端同步 | UI 面向桌面，移动端是壳；无打卡 |

| `Splode/pomotroid` | 5.6k | Rust/Tauri | Win/mac/Linux | MIT | 桌面番茄钟 UI、托盘、主题、白噪音 | 纯计时器，无任务 |

| `FriesI23/mhabit`（Table Habit） | 1.7k | Dart/Flutter | Android + 桌面 | Apache-2.0 | **Flutter 跨端打卡**的完整实现（含桌面） | 只有习惯，无任务 |
| `InlitX/streak` | 1.2k | Dart/Flutter | Android/Win/Linux | GPL-3.0 | **Flutter + Android + Windows 三端同码**的真实样本：`flutter_local_notifications` + `home_widget` + `audioplayers` + `wakelock` | 只有打卡 |
| `TechbeeAT/jtxBoard` | 0.7k | Kotlin/Compose | Android | GPL-3.0 | VTODO/VJOURNAL 标准映射、Compose + Glance 小组件 | 依赖 DAVx5，无独立同步 |
| `AppFlowy-IO/AppFlowy` | 79.1k | Dart/Rust | 全平台 | AGPL-3.0 | 本地优先 + 块编辑器的架构范式 | 体量巨大，非待办专用 |

### 3.2 结论

1. **空白明确**：没有任何开源项目同时做到「任务 + 番茄 + 打卡 + Android 原生体验 + Windows 桌面 + 本地优先同步」。自研壳是唯一路径。
2. **可借鉴的模块是分离的**：
   - 任务内核 → Tasks.org / Super Productivity
   - 打卡与统计 → Loop Habit / Table Habit
   - 桌面番茄 → Pomotroid
   - 多端同码工程结构 → Streak（Flutter，最有价值）
   - 游戏化奖励 → Habitica（对应 Pinch 的奖励商店）
3. **许可证要注意**：Tasks.org、Loop Habit、Streak、jtxBoard 均为 **GPL-3.0**，只可"读思路"，不可复制代码到闭源项目。`super-productivity`（MIT）、`mhabit`（Apache-2.0）、`pomotroid`（MIT）可安全参考实现。
4. **可直接复用的技术资产**：
   - `drift` 官方自带一个 **全平台 Flutter 待办示例**（Android/iOS/Windows/Linux/macOS/Web），可直接作为工程骨架。
   - `flutter_local_notifications` 已支持 6 平台（含 Windows Toast）。
   - RRULE 解析可用 `rrule` / `recurrence` 类库，避免手写重复规则。

## 4. 产品定义（V1）

### 4.1 定位

> 一个**不用登录、离线可用**的个人任务与专注工具：3 秒记下任务，今天该做什么一眼看到，专注有记录，习惯有反馈。

差异化（对抗滴答清单的三点）：

1. **本地优先**：数据在设备上，云同步是可选项，不是前提。
2. **任务—专注—打卡闭环**：一个任务可被"专注"，专注时长回写任务；习惯可绑定专注；目标聚合三者进度。
3. **复盘导向**：不做花哨视图，把"完成率 / 专注时长 / 连续天数"做成每日一屏。

### 4.2 功能优先级

| 优先级 | 模块 | 具体内容 |
| --- | --- | --- |
| **P0（MVP 必须有）** | 任务核心 | 增删改查、子任务、清单、标签、优先级、开始/截止、备注、排序拖拽 |
| | 智能清单 | 今天、最近 7 天、收件箱、已完成、逾期 |
| | 提醒 | 单次/重复提醒、通知按钮（完成/稍后）、开机恢复 |
| | 重复任务 | 每天/每周/每月/自定义、完成式与固定式 |
| | 日历 | 月视图 + 周视图、任务拖拽改期 |
| | 番茄 | 番茄/正计时、前台服务、结束时通知、任务耗时回写 |
| | 打卡 | 习惯创建、每日打卡、streak、月历热力图 |
| | 统计 | 今日完成数、专注时长、习惯完成率 |
| | 系统 | 本地备份/恢复(JSON)、深浅色、中英 |
| | Android | 桌面小组件（今日清单）、分享接收、快捷方式 |
| **P1（V1.1）** | 四象限 / 看板 | 按优先级与状态分列 |
| | 心情打卡 | 情绪日历 + 趋势（Pinch 差异化） |
| | 目标 | 目标聚合任务/习惯/专注进度 |
| | Windows 增强 | 托盘常驻、全局快捷键、迷你便签、开机自启、MSIX 打包 |
| | 统计增强 | 趋势图、热力图、周报卡片导出图片 |
| **P2（V2）** | 同步 | WebDAV / 自建服务端，字段级合并 |
| | 奖励系统 | 积分与兑换（Pinch 的乐趣来源） |
| | CalDAV | 与系统日历/Nextcloud 互通 |
| | 自然语言 | "明天三点"解析、语音输入 |
| | 白噪音 | 雨声/篝火等场景音 |

### 4.3 明确不做

协作/共享清单、团队指派、日历订阅、多主题商店、白板、AI 助手、Web 端、iOS（一期）。

## 5. 技术栈评估

### 5.1 四条路线对比

| 维度 | **Flutter** | React Native (Expo) | KMP + Compose Multiplatform | 原生双端 |
| --- | --- | --- | --- | --- |
| Android 体验 | 优（自绘，一致） | 良（贴近原生控件） | 最优（原生） | 最优 |
| Windows 桌面 | **官方稳定支持** | RN-Windows 社区方案，Expo 不支持 | Compose Desktop（JVM，可用） | 需 WinUI 重写 |
| 代码复用 | 90–95% | 85–90%（仅移动） | 60–75% | 0 |
| 自绘 UI 一致性 | 高 | 中 | 中 | 低 |
| 生态成熟度 | pub.dev 完善，桌面插件齐全 | npm 最大，但桌面插件少 | 生态最小 | — |
| 学习成本 | Dart，中等 | TS，低 | Kotlin + Gradle，高 | 高 |
| 包体积 | 偏大（引擎约 +8–15MB） | 中 | 小 | 小 |
| 通知/小组件 | 插件齐全，需少量原生代码 | 需 config plugin | 原生直写最灵活 | 最灵活 |
| 适合本项目 | **推荐** | 备选（若只做 Android） | 次选（若团队是 Kotlin） | 不推荐（人力翻倍） |

**选型理由**：本项目 80% 的界面是自绘的列表/日历/图表，Flutter 的一致性收益最大；Windows 是明确需求，而 RN 的 Windows 方案在 2026 年仍需维护独立工程；Flutter 的 `drift` + `flutter_local_notifications` + `home_widget` 三个关键能力全部成熟且有真实三端项目验证（`InlitX/streak`）。

### 5.2 推荐技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Flutter 3.4x / Dart 3.9+ | 单工程，`android` + `windows` 两个 target |

| 键值/设置 | shared_preferences | 轻量配置 |
| 通知 | flutter_local_notifications 23.x + timezone | Android 精确闹钟 + Windows Toast |
| 后台计时 | flutter_foreground_task | 番茄钟前台服务，防被杀 |
| 小组件 | home_widget（Android AppWidget / Glance 桥） | 今日清单 |
| 图表 | fl_chart | 趋势、环形、热力图自绘 |
| 音频 | just_audio / audioplayers | 白噪音、完成音效 |

| 测试 | flutter_test + integration_test + golden | 关键路径回归 |

### 5.3 备选：KMP 的适用条件

仅当满足以下全部条件时才改选 KMP：团队已熟悉 Kotlin；iOS 是硬需求；愿意为 Windows/iOS 各写一套 UI。否则 Flutter 的交付效率优势压倒性。

### 5.4 数据模型草案

```sql
-- 清单
lists(id TEXT PK, name TEXT, color INT, icon TEXT, folder_id TEXT,
      sort_order INT, is_inbox INT, archived INT,
      created_at INT, updated_at INT, deleted_at INT, rev INT)

-- 任务（核心表）
tasks(id TEXT PK, list_id TEXT, parent_id TEXT,
      title TEXT, notes TEXT,
      status INT,            -- 0 待办 1 完成 2 取消
      priority INT,          -- 0 无 1 低 2 中 3 高
      start_at INT, due_at INT, all_day INT,
      estimate_min INT, spent_min INT,
      repeat_rule TEXT,      -- RFC5545 RRULE
      repeat_mode INT,       -- 0 固定日程 1 完成后顺延
      repeat_from_id TEXT,   -- 重复实例的母任务
      remind_json TEXT,      -- [{offset:-600,type:notify},{repeat:true}]
      completed_at INT, pinned INT, sort_order REAL,
      created_at INT, updated_at INT, deleted_at INT, rev INT, device_id TEXT)

-- 标签
tags(id TEXT PK, name TEXT, color INT, updated_at INT, deleted_at INT)
task_tags(task_id TEXT, tag_id TEXT, PRIMARY KEY(task_id, tag_id))

-- 习惯
habits(id TEXT PK, name TEXT, icon TEXT, color INT,
       freq_type INT,      -- 0 每日 1 每周N次 2 自定义星期 3 每月
       freq_config TEXT, target_count INT, unit TEXT,
       remind_at TEXT, archived INT, sort_order INT,
       created_at INT, updated_at INT, deleted_at INT)
habit_logs(id TEXT PK, habit_id TEXT, date TEXT, count INT,
           note TEXT, created_at INT, updated_at INT, deleted_at INT)

-- 专注
focus_sessions(id TEXT PK, task_id TEXT, mode INT,
               started_at INT, ended_at INT,
               planned_sec INT, actual_sec INT,
               note TEXT, updated_at INT, deleted_at INT)

-- 索引（关键）
CREATE INDEX idx_task_list_status_due ON tasks(list_id, status, due_at);
CREATE INDEX idx_task_parent ON tasks(parent_id);
CREATE UNIQUE INDEX idx_habit_log ON habit_logs(habit_id, date);
CREATE VIRTUAL TABLE tasks_fts USING fts5(title, notes, content='tasks', content_rowid='rowid');
```

设计要点：

1. **ID 用 UUIDv7**（时间有序，便于同步游标与排序）。
2. **软删除 + `rev` 版本号**，所有表统一，为后续同步留口子。
3. **时间为 Unix 毫秒 + 独立 `timezone` 设置**，跨时区不丢语义。
4. **重复规则存 RRULE 字符串**，不存 JSON 结构，便于与 CalDAV 互通。
5. **智能清单不建表**，是查询（`due_at < 今日 24:00 AND status = 0`），避免数据冗余。

### 5.5 同步方案三选

| 方案 | 实现成本 | 适用 | 风险 |
| --- | --- | --- | --- |
| **A. 单机 + 手动导出/导入 JSON** | 极低（2 人日） | V1 默认 | 无法自动多端 |
| **B. WebDAV 文件夹同步**（坚果云/Nextcloud） | 中（10 人日） | V1.5 推荐 | 需处理冲突与文件锁；每次全量或分片 |
| **C. 自建服务端 / Supabase** | 高（20+ 人日） | V2 | 运维成本、登录体系、隐私承诺被打破 |

推荐路径：**A → B**。同步协议用「字段级 LWW + `updated_at` + `device_id` + 墓碑记录」，冲突时保留两份并在 UI 提示，不做静默覆盖（这是 Pinch 用 CRDT 的原因，但 CRDT 对单人工具过重）。

### 5.6 Android 适配清单（决定"能不能用"）

| 项 | 要求 | 备注 |
| --- | --- | --- |
| 通知权限 | Android 13+ 运行时申请 `POST_NOTIFICATIONS` | 在用户开启提醒时申请，不在启动时弹 |
| 精确闹钟 | `SCHEDULE_EXACT_ALARM` + `canScheduleExactNotifications()` 检查 | Android 14 起默认不授予；`USE_EXACT_ALARM` 仅闹钟/日历类可申报，商店会审核 |
| 开机恢复 | `RECEIVE_BOOT_COMPLETED` + 重排未来提醒 | 否则重启后全部失效 |
| 番茄前台服务 | `flutter_foreground_task`，常驻通知显示剩余时间 | 否则锁屏后计时被杀 |
| OEM 保活 | 引导页跳转自启动/电池白名单（小米/华为/OPPO/vivo） | 参考 dontkillmyapp.com，必须做引导 |
| 小组件 | `home_widget` + 原生 AppWidget | 只做"今日清单"一个，别贪多 |
| 分享接收 | `intent-filter` 接文本/链接，直接建任务 | 捕获摩擦最低的入口 |
| 通知动作 | 「完成」「稍后 1 小时」直接落库 | 需后台 isolate 处理 |
| 快捷方式 | 长按图标 → 新建任务 / 开始专注 | `shortcuts.xml` |

### 5.7 Windows 适配清单

| 项 | 方案 | 限制 |
| --- | --- | --- |
| 通知 | `flutter_local_notifications` 的 Toast | **不支持重复通知**；未用 MSIX 打包时 `cancel` 无效 |
| 打包 | `msix` 包 | 有包标识才能正常操作通知 |
| 托盘 | `tray_manager` | 关闭窗口最小化到托盘 |
| 全局快捷键 | `hotkey_manager`（Ctrl+Shift+A 快速添加） | 需处理冲突 |
| 开机自启 | 注册表 / 启动文件夹 | 给用户开关 |
| 迷你便签 | 无边框置顶小窗 | 对应滴答的"桌面便签" |
| 布局 | 三栏（导航 - 列表 - 详情） | 与移动端共用组件，按断点切换 |

## 6. 实现难度评估

### 6.1 模块 × 难度 × 工时（人日，单人 + AI 辅助）

| 模块 | 难度 | 工时 | 主要难点 |
| --- | --- | ---: | --- |
| 工程骨架 / 主题 / 响应式布局 | 低 | 5 | 移动底部 Tab 与桌面三栏的组件复用 |
| 任务 CRUD + 快速添加 | 中 | 8 | 乐观更新、连续输入、撤销 |
| 清单 / 标签 / 智能清单 / 筛选 | 中 | 8 | 派生查询的性能与一致性 |
| 任务详情（子任务 / 备注 / 附件） | 中 | 10 | Markdown 编辑、图片压缩、附件管理 |
| **提醒调度** | **高** | 12 | 权限、时区、开机恢复、500 闹钟上限、OEM 杀后台 |
| **重复规则** | **高** | 12 | RRULE 解析、完成式顺延、例外日、提醒重排 |
| 日历（月/周 + 拖拽） | 高 | 12 | 手势冲突、跨天任务、性能 |
| 看板 / 四象限 | 低 | 6 | 拖拽状态流转 |
| **番茄钟** | 中高 | 10 | 前台服务、锁屏计时、通知动作、耗时回写、跨设备续计时 |
| 习惯打卡 | 中 | 8 | streak 边界（跨时区/补卡/跳过的判定） |
| 统计图表 | 中 | 6 | 数据聚合与空态 |
| 小组件（Android） | 中高 | 8 | 原生 AppWidget + 数据同步 |
| 设置 / 主题 / i18n / 备份 | 低 | 6 | — |
| Windows 适配 | 中 | 6 | 托盘、快捷键、MSIX、通知限制 |
| 同步（WebDAV） | 高 | 10 | 冲突合并、增量、断点 |
| 打磨 / 测试 / 发布 | 中 | 12 | 真机矩阵、OEM 兼容、商店合规 |
| **合计** | | **≈135** | 含同步；不含同步约 125 |

**MVP（P0 全部，不含同步、看板、心情、目标、Windows 增强）≈ 60 人日**，按每周 5 个有效人日计约 **12 周**；熟练后 8～10 周可交付。

### 6.2 五个真正的难点（按风险排序）

1. **提醒可靠性**（Android）：这是"待办工具"的生命线。权限被拒、OEM 杀后台、重启丢失、时区切换，任一场景失败用户就会弃用。必须做降级策略 + 引导页 + 真机矩阵测试。
2. **重复任务与提醒的重排**：一个每日重复任务不该预排 365 个闹钟。正确做法是"只排未来 N 天，触发后滚动排下一次"，并处理"完成后顺延"与"固定日程"两种语义。
3. **日历手势与性能**：月视图一屏 42 天 × 每天多条任务，拖拽与滚动的冲突、跨月渲染、虚拟化，是纯工程量。
4. **跨端 UI 一致性**：同一组件在触屏（44dp 点击区）与鼠标（hover、右键菜单、快捷键）下语义不同，必须做输入模式适配，而不是简单缩放。
5. **同步冲突**：字段级 LWW 看似简单，但"删除 vs 编辑"、"重复任务实例"、"习惯补卡"三类冲突最易出错。

### 6.3 容易被低估的成本

- 应用图标 / 启动图 / 商店截图 / 隐私政策（上架必需，约 3–5 人日）
- 真机测试（至少 3 台不同 OEM 的 Android + 1 台 Windows）
- 数据迁移与备份格式的向后兼容（一旦发版就不能随便改）
- 无障碍与字号适配（系统字体放大后布局崩坏是常见差评源）
