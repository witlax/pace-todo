| 平台 | 文件 | 说明 |
| --- | --- | --- |
| Android | `dist/tasks-1.0.0-release.apk` | 通用包，minSdk 26（Android 8.0） |

构建命令：

```bash
cd app
flutter build apk --release            # 输出 build/app/outputs/flutter-apk/app-release.apk
cp build/app/outputs/flutter-apk/app-release.apk ../dist/tasks-1.0.0-release.apk
```

`version` 在 `pubspec.yaml`（`1.0.0+19`），关于页显示的版本在 `lib/core/app_info.dart`（`kAppVersion` / `kAppBuild`），**两处一起改**。

## 2. 签名

V1 起使用独立发布密钥，不再用 debug 签名。

```bash
# 只做一次。已生成过就跳过。
cd app/android/app
keytool -genkeypair -v -keystore release-key.jks -storetype PKCS12 \
  -keyalg RSA -keysize 2048 -validity 10950 -alias tasks \
  -storepass <你的口令> -keypass <你的口令> \
  -dname "CN=Tasks, OU=Personal, O=Witlax, L=Beijing, ST=Beijing, C=CN"
```

`app/android/key.properties`（**不入库**，已在 `.gitignore`）：

```properties
storePassword=...
keyPassword=...
keyAlias=tasks
storeFile=release-key.jks
```

`app/android/app/build.gradle.kts` 的逻辑：有 `key.properties` 就用 release 签名，没有就回退 debug —— 保证新克隆的仓库也能 `flutter run --release`，但正式分发必须用带密钥的构建。

> ⚠️ **换签名的代价**：此前用 debug 签名安装的包无法覆盖升级，需要先卸载（数据会丢，先导出备份）。1.0.0 是第一次正式签名，建议在此版本让用户重装一次。
>
> 密钥文件请自行备份到密码管理器。丢失后无法再发布同包名更新（只能换包名，等于新应用）。

验证签名：

```bash
keytool -printcert -jarfile dist/tasks-1.0.0-release.apk
# 或用 apksigner verify --print-certs
```

## 3. 图标与素材

图标由脚本生成（无第三方依赖，机器上没有 PIL 也能跑）：

```bash
cd app && python scripts/make_icon.py
```

产出 5 档 `mipmap-*/ic_launcher.png`（48/72/96/144/192）+ `docs/assets/icon-512.png` + `icon-1024.png`，
同时 `mipmap-anydpi-v26/ic_launcher.xml` 走自适应图标（Android 8+ 圆形/圆角裁剪生效），
前景是矢量勾（`drawable/ic_launcher_foreground.xml`），背景是深绿渐变（`drawable/ic_launcher_background.xml`）。

商店素材（应用商店 / 酷安 / GitHub Release）：

| 素材 | 规格 | 状态 |
| --- | --- | --- |
| 应用图标 | 512×512 PNG，无透明角 | `docs/assets/icon-512.png` |
| 高清图标 | 1024×1024 | `docs/assets/icon-1024.png` |
| 手机截图 | 1080×1920 起，至少 4 张 | `docs/assets/screens/`（今天 / 目标 / 智能清单 / 白噪音） |

| 功能图 | 1024×500，横版 | 可选 |
| 应用描述 | 见 §5 | 本文档 |

## 4. 隐私说明

关于页「隐私说明」的正文只有一份，定义在 `lib/core/app_info.dart` 的 `kPrivacyText`。
商店填写隐私政策时可以整段复制，不要另写一套口径。核心四条：

1. **无网络权限**。`AndroidManifest.xml` 里没有 `INTERNET`，安装包内无统计 / 广告 / 崩溃 SDK。
2. **数据只在本机** SQLite，无账号、无同步。
3. **权限最小**：通知、精确闹钟、开机自启、前台服务（专注倒计时）、相册/文件（仅用户主动选文件时）。
4. **日志不含内容**：只记事件（「已排提醒」「迁移完成」），内存中保留，退出即清空。

## 5. 商店文案

**应用名**：Pace（中文副标题「节奏」）

**一句话（30 字内）**：
本地待办 + 习惯打卡 + 专注计时，数据只存在你手机里。

**短描述（80 字内）**：
把今天要做的事排清楚：清单、四象限、日历、看板四种视角；习惯按周/按月/隔天算，连续天数不会算错；25 分钟专注带正计时与白噪音。不登录、不联网、不收集信息。

**长描述**：

> **为什么又一个待办应用**
>
> 大多数待办应用在解决「多设备同步」，代价是账号、订阅、隐私和一堆你不需要的协作功能。
> **Pace** 解决的是另一件事：**打开就能看清今天该干什么，关掉之后什么都不过问**。
>
> **四种视角，同一份数据**
> - 今天：清单与四象限左右滑动，任务按「逾期 / 今天 / 之后 / 未排期」自动分组
> - 视图：工作台、日历（月 / 周 / 三日）、看板、卡片，四页横滑切换
> - 四象限直接写出判定规则（重要与否 × 3 天内与否），拖一下就换格
> - 日历支持拖拽改期、按天回顾、导出回顾图片
>
> **习惯按规则算，不按感觉算**
> 每周一三五、每月 15 号、每隔 3 天，都按「计划日」推进连续天数——周二没打卡不会断签。
> 喝水这类一天多次的习惯，点一次记一次，打满目标才算完成。
>
> **专注是本地的番茄钟**
> 15 / 25 / 45 分钟或自定义，支持正计时；锁屏后前台服务保活；结束有结算页，可以补记或修正时长；
> 连续专注 50 分钟会提示起身；白噪音四种场景运行时生成，不占包体。
>
> **目标把散落的动作串起来**
> 关联任务看完成比例、关联习惯看打卡次数、专注看累计分钟，或者手动记录进度。
>
> **数据是你的**
> 无账号、无网络权限、无统计 SDK。备份是 zip（含附件），恢复后附件数量可核对。
>
> **已知边界**
> V1 不做云同步与 CalDAV；通知上的「完成 / 稍后」按钮在部分国产 ROM 上需要点开应用才生效（会正常完成，只是会亮屏）。

**更新说明（1.0.0）**：
首个正式版。四种任务视角、习惯频率模型、专注与白噪音、目标聚合、备忘录与心情、本地备份、桌面两栏与快捷键。

## 7. 性能基线

`test/perf_baseline_test.dart`（内存库，Windows 台式机）：

| 指标 | 实测 | 阈值 |
| --- | --- | --- |
| 写入 1000 条任务 | 0.8–1.2 s | < 30 s |
| 全量读取 1000 条 | 65–70 ms | < 3 s |
| 冷启动建库（schema v6） | < 200 ms（首次） | 目测 |

阈值故意放宽 5–10 倍：它拦的是数量级退化，不是机器抖动。
真机首屏建议在 1.0.0 发布前用 `flutter run --profile` 手测一次上表。

## 8. 已知限制（如实写）

| 项 | 现状 | 影响 |
| --- | --- | --- |
| 通知动作 | 点击「完成」会把应用拉到前台再写库 | 部分 ROM 上会亮屏，但功能正确 |
| 白噪音 | 运行时生成 PCM，6 秒循环 | 极少数机型首个循环有轻微接缝 |
| 云同步 / CalDAV | V1 不做 | 多设备需手动备份恢复 |
| Windows 包 | 本轮未打包 | 代码已支持，需在 Windows 上 `flutter build windows` |
| 表格视图 / 甘特 | 不做 | 手机不可用 |
| 悬浮胶囊 | 仅应用内 | 系统级悬浮窗需额外权限，V1 不做 |

## 9. 发布步骤

1. `cd app && flutter analyze && flutter test` 全绿
2. 改版本：`pubspec.yaml` + `lib/core/app_info.dart`
3. `python scripts/make_icon.py`（图标有改动时）
4. `flutter build apk --release`，确认 `keytool -printcert` 显示的是发布证书
5. 复制到 `dist/tasks-<版本>-release.apk`
6. 真机装一次，按 §6 勾一遍
7. 截图：今天 / 四象限 / 日历三日 / 专注 / 目标 / 深色模式（已有 4 张在 `docs/assets/screens/`，缺四象限、三日视图、深色）
8. 更新 `CHANGELOG.md` 与 `DEVLOG.md`
9. `git tag v1.0.0 && git push --tags`，GitHub Release 附 APK 与截图
10. 商店提交：图标、截图、短描述、长描述、隐私说明
