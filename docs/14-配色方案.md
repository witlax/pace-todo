# 配色方案

> 1.4.0 · 参考 [PaletteMaker](https://palettemaker.com/app) 的取色范式
> 代码位置：`app/lib/app/tokens.dart`（色值）与 `app/lib/app/theme.dart`（映射）

---

## 1. 取色依据

PaletteMaker 是一个「把配色套进真实版型看效果」的工具，它本身不提供固定色板（每次生成都不同）。
它给的是三条可用的方法论，这次就按这三条重新配平：

1. **低饱和主色**：主色不做纯色高饱和，压掉 20–30% 的彩度，长时间看不累。
2. **60-30-10 比例**：中性色承担约 60% 面积（背景、卡片），主色 30%（可点元素、选中态），
   暖色强调 10%（今天、等级、进行中）。
3. **互补 / 分裂互补定强调色**：主色是绿，强调就用它的互补暖色（陶土橙），
   而不是再找一个近似的蓝——近似色会互相削弱。

取样参考（该站颜色页给出的实际 hex 与搭配建议）：
- Teal Green `#25A385` —— 配合 dark burnt orange 做分裂互补
- Burnt Sienna `#A93400` —— 与 steel blue 互补

我们的主色比 `#25A385` 更深（`#1E6E63`）：UI 里主色要承载白字，`#25A385` 的对比度不够。

## 3. 落地方式

```
AppPaletteName（设置里的三选一）
   └── AppPaletteScheme（seed / 背景 / 语义色 / 重要性四色）
          ├── AppTheme.light/dark  → ColorScheme + AppColors 扩展
          └── paletteProvider      → 重要性四色（含色盲友好覆盖）
```

- 页面**不再写十六进制**：主色取 `Theme.of(context).colorScheme.primary`，
  强调/完成/逾期取 `context.appColors.accent / done / warn`，
  重要性取 `context.appColors.palette.of(emphasis)` 或 `ref.watch(paletteProvider)`。
- 色觉友好开关优先级最高：打开后四色固定为 品红 / 琥珀 / 青 / 灰，不受方案影响。
- 深浅色切换时 `paletteProvider` 会按当前亮度取对应那一套（`PlatformDispatcher` 兜底跟随系统）。

---

## 4. 为什么这么改

改之前的三个问题：

| 问题 | 现象 | 现在 |
| --- | --- | --- |
| 主色与重要性色撞车 | 主色是蓝，低优先级也是蓝，看到蓝色不知道是「能点」还是「不重要」 | 主色墨绿，低优先级是青灰蓝，语义分开 |
| 强调色太亮 | 等级条 / 今天用 `#E4762F`，在浅灰底上跳 | 压到 `#C2703A`，只在少数位置出现 |
| 语义色分散 | 完成态有 `#0F6E56` 与 `#2E7D57` 两个绿，逾期有 `#C2333A` 与 `#C2410C` 两个红 | 统一由 `AppColors` 提供，一处改全站生效 |
