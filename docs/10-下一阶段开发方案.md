### 1.1 已经能用的（有代码、有实测）

| 域 | 能力 |

### 1.2 关键缺口（按真实影响排序）

| # | 缺口 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1 | **习惯周期只存不判** | `freqConfig` 写入 `weekly:1,3,5` 等，但 `habit_detail_page` 的「计划打卡」直接用整月天数，`calcStreak` 按自然日连续算 | 「按周/按月/每隔几天」目前只是文案；完成率与连续天数**算错** |
| 2 | **每天次数不判定** | `targetCount` 只用于卡片显示「每天 N 次」 | 多次类习惯（喝水 8 杯）无法按次完成 |
| 3 | **无正计时** | `focus_controller` 只有倒计时 | 指尖时光的核心模式缺失 |
| 4 | **专注不能补时/修正** | 结算页只有「休息/再来一轮」 | 真实使用中提前结束就会丢时长 |
| 5 | **习惯×专注未联动** | 无 habit 与 focus 的关联字段 | Pinch 特色（打卡即番茄）缺失 |
| 6 | **无目标系统** | 无 goals 表 | 任务/习惯/专注没有聚合层，复盘中「为什么做」缺失 |
| 7 | **无卡片视图（任务）** | `ViewMode` 只有 dashboard/calendar/board | 与 Pinch、滴答的「卡片/磁贴」形态差一档 |
| 8 | **通知无操作按钮** | 只有点击打开任务 | 滴答的「完成 / 稍后提醒」缺失，提醒价值打折 |
| 9 | **无智能清单** | 只有普通清单 | 滴答的「今天/最近7天/有内容时显示」三态缺失 |
| 10 | **习惯无排序入口** | `sortOrder` 字段存在，无拖拽 UI | 习惯多了以后顺序不可控 |
| 11 | **完成无正反馈** | 任务完成无动效/触感 | 低成本的体验损失 |
| 12 | **桌面右栏未落地** | 详情仍是整页 route | 三栏只做了两栏 |

### 1.3 明确不做（避免被「复刻」绑住）

| 项 | 理由 |
| --- | --- |
| 奖励/金币/商店 | 与「本地优先、零负担」定位冲突，长期维护成本高 |
| 思源文档任务收集、块属性徽章 | 依赖思源数据模型，离开思源无意义 |
| CalDAV / 云同步 | V1 定位本地优先，同步是 2.0 的独立课题 |
| 表格视图、甘特图 | 手机不可用；桌面另议 |
| 难度/积分、底部字符统计 | 服务游戏化，不是我们的目标 |

## 2. 与 Pinch 的模型对齐（只复刻模型）

Pinch 最值得抄的不是界面，是三个模型：

### 2.1 频率模型（最高优先级）

```
freqConfig:
  daily
  weekly:1,3,5          // 周几
  weekly:3/whenNeeded    // 每周 N 次（新增）
  monthly:15
  interval:3            // 每 N 天
```

派生三件事，必须由同一份纯函数给出，禁止各页各算：

| 派生量 | 定义 |
| --- | --- |
| `scheduledOn(day)` | 该日是否为计划日 |
| `plannedBetween(from,to)` | 区间内计划次数（weekly N 次按周折算） |
| `streak(logs, today)` | 只在计划日推进；非计划日不打断；计划日未打卡才算断 |

落点：新建 `app/lib/features/habits/habit_schedule.dart`（纯函数，无 Flutter 依赖），
`habit_detail_page` / `habit_page` / `habit_stats_page` / 热力图统一改用它，
并补 `test/habit_schedule_test.dart`（≥12 条用例：跨月、闰年、周 N 次、隔天、补卡）。

### 2.2 完成模型

- 次数型：`targetCount`，`habit_logs.count` 累加，达到目标才算当日完成。
- 时长型（P2）：`targetMinutes`，从专注会话累计。

schema v5 给 `habit_logs` 加 `count INTEGER DEFAULT 1`，给 `habits` 加 `targetMinutes INTEGER NULL`。

### 2.3 目标模型（聚合层）

四种进度方式，与 Pinch 一致：

| 方式 | 数据来源 |
| --- | --- |
| 任务 | 关联任务完成数 / 总数 |
| 习惯 | 关联习惯打卡次数 / 计划次数 |
| 专注 | 关联专注分钟 / 目标分钟 |
| 手动 | 直接写 progress 0–100 |

表：`goals(id, title, note, mode, target, current, dueAt, status, sortOrder, createdAt, updatedAt)`
+ `goal_links(goalId, refType, refId)`。

原 `docs/06` 的 M6/M7 已不适用（跨端捕获优先级下降，交互深挖实际更重要）。改为按**用户闭环**排：

## 5. 技术债与工程优化

| 债 | 现状 | 处理 |
| --- | --- | --- |
| schema 反复迁移 | v1→v4 四次 | **一次做到 v5**（goals / goal_links / smart_lists / habit_logs.count / habits.targetMinutes / mood_entries），带迁移测试 |
| 周期判定散落 | 各页各算 | 抽 `habit_schedule.dart` 纯函数 + 单测 |
| 详情页不可嵌入 | 整页 route | 拆 `TaskDetailBody`（无 Scaffold），手机 push、桌面右栏 |
| 通知动作 | 只有点击 | `AndroidNotificationAction` + 后台 isolate 写入，注意幂等 |
| widget 测试薄弱 | 3 个文件 | 补：打卡确认、排期面板、备忘录视图切换、通知动作回调 |
| 无性能基准 | 无 | 加 `integration_test/perf_test.dart`，记录首屏与滚动帧率 |
| 无截图回归 | 手工 headless | 固化 `scripts/shots.mjs`，与 `preview/` 对齐比对 |
| 桌面未真机验证 | 仅代码 | 每版构建 Windows 产物，跑一次三栏 + 快捷键 |
| 空态与无障碍 | 部分 | 统一空态组件 + Semantics 标签补全 |

**工作流优化（延续现有留痕，但加一环）**

```
preview 更新（规格） → 实现 → flutter analyze + test → 模拟器截图核对
   → DEVLOG 记账 → commit + push → 版本包归档
```

新增：**每个版本交付时附「验收清单勾选表」**（本文件 §4 的验收项），避免再出现「功能做了但没生效」这类问题。

### 测试与验证

- `flutter test`：**67 项通过**（原 50 + 目标 7 + 性能/迁移 2 + 通知动作 8）。
- `flutter analyze`：0 issue。
- 模拟器（Android 15 / API 35）实测：目标创建 → 关联三个任务 → 勾完一个 → 进度 1/3 33%；智能清单按内容出现/隐藏；专注页白噪音面板四种场景可切、可关闭；通知带两个动作按钮；点通知正文直达任务详情。
- 通知按钮点击的端到端未在模拟器验证成功（`adb input tap` 打不进 SystemUI 的 action 按钮），已在 `docs/11` §6.6 标为真机手测项；payload 解析与落库两端另有 8 条单测覆盖。

### 已知取舍

- 目标进度不自动改目标状态（达成后仍显示在列表，需手动完成/归档）：自动改状态会在误关联时把目标「锁死」。
- 专注目标从「目标创建时刻」开始累计，用结束时间判断，避免跨过创建时刻的一轮被漏掉。
- 白噪音用 6 秒循环而非无损长音频：包体优先，接缝已做 0.35s 淡入淡出。
