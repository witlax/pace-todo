# V1.0 功能预览与复刻对照

> 回答三个问题：**做了哪些、和参照产品像到什么程度、手机上好用在哪。**
> 配套：可交互界面预览 `preview/v1-preview.html`；阶段计划 `docs/06-阶段里程碑与验收.md`。
> 决策前提：`com.witlax.tasktodo`、Android + Windows、V1 不做同步、打卡为一级功能（ADR-0009）。

---

## 1. 版本定调

**一句话**：一个不用登录、离线可用的个人任务与专注工具——3 秒记下任务，今天该做什么一眼看到，专注有记录，习惯有反馈。

三条设计原则（冲突时按顺序取舍）：

1. **先能记，再能理**：捕获路径永远不超过两步，整理可以事后做。
2. **一屏一域**：今日、日历、专注、习惯各自独立，不把六种视图塞进一个页面。
3. **正反馈要立刻发生**：勾选、打卡、计时结束都有明确反馈，且 3 秒内可撤销。

## 3. 三个超越点

参照产品各有短板，这三处我们做得更好：

1. **专注结束可修正**：滴答与 Pinch 都允许补时，但不允许"这次专注其实只有 18 分钟"的诚实修正；我们把它做成结束页的一等操作，并在统计里区分"计时时长"与"有效时长"。
2. **打卡跨时区安全**：多数产品用本地日期字符串存打卡，跨时区或旅行后会错位；我们用"归属日"（本地日 + 时区快照）计算，跨时区不改写历史。
3. **零登录、零网络即可完整使用**：滴答必须账号，Pinch 依赖思源；我们把"离线可用"作为默认，而不是降级模式。

## 4. 移动端交互适配

### 4.1 导航结构

```
┌──────────────────────────────┐
│  今天                   [⋯]  │
│  ┌──────────┬──────────┐     │
│  │   任务   │   专注   │     │  ← 首页模式切换，替代独立 Tab
│  └──────────┴──────────┘     │
│  ┌────────────────────────┐  │
│  │ 搜索任务、备忘录        │  │  ← 仅任务模式显示
│  └────────────────────────┘  │
│  上午                        │
│  ○ 写周报            09:30   │
│  ● 买菜              全天    │
│                        (+)   │  ← FAB，右下，拇指区
├──────────────────────────────┤
│ 今天   日历   习惯   设置     │  ← 中间项可配置，最多 3 个
└──────────────────────────────┘
侧边抽屉：收件箱 · 清单 · 标签 · 备忘录 · 已完成 · 回收站
```

**可配置规则**：`今天` 固定在第一位、`设置` 固定在最后，两者不可移除；中间最多 3 个位置，从 `日历 / 习惯 / 备忘录` 勾选并可拖动排序。默认 `今天 / 日历 / 习惯 / 设置`。配置在 设置 → 导航栏，带实时预览条与拖动排序（ADR-0014）。

**专注为什么不在 Tab 里**：专注是"进入一种状态"，不是"去另一个地方"——它没有独立的数据集合，只有一段正在跑的计时。放在首页顶部做模式切换，切走时任务上下文还在。计时运行时，Tab 栏上方会出现 18 dp 运行条「专注中 18:32 · 写周报」，点回计时页。桌面端仍保留左侧"专注"入口，因为大屏没有"首页模式"的概念。

**备忘录为什么默认不进 Tab**：它是"查资料"而非"每天处理"的域，占常驻位置会稀释主线。需要时可在 设置 → 导航栏 打开，打开后占据中间一个位置。

### 4.2 尺寸与可达性

| 项 | 规范 | 理由 |
| --- | --- | --- |
| 最小触控区 | 48×48 dp | Material 下限，避免误触 |
| 列表行高 | 56 dp（紧凑 48） | 一屏 10～12 条，信息密度与可点性平衡 |
| 主要操作位置 | 屏幕下 1/3 | 单手可达区 |
| 顶部操作 | 只用图标，≤2 个 | 顶部是双手区，不放高频操作 |
| 字号 | 正文 15–16 sp，次要 13 sp | 兼顾信息量与可读性 |
| 圆角 | 卡片 12，弹层 16，按钮 10 | 统一视觉语言 |

### 4.4 五个关键流程

**① 3 秒捕获**

```
点 FAB → 底部弹层升起（键盘同时弹出，输入框已聚焦）
      → 输入标题 → 直接回车保存到收件箱
      → 需要日期：点上方快捷条（今天 / 明天 / 下周一 / 自定义）
```

关键：**默认不强迫选清单、不强迫设日期**。整理是第二动作，不是捕获的前置条件。

**② 完成一条任务**

```
点圆圈 → 勾选动画 + 轻触觉反馈 → 任务下沉并淡出
      → 底部出现「已完成 · 撤销」（3 秒）
```

关键：完成必须有反馈，且误触可挽回。3 秒后真正落库为已完成。

**③ 改期**

```
左滑 → 点「延期」→ 弹出日期快捷条（今天/明天/下周/自定义）
或：进详情 → 点日期 chip → 同一套快捷条
```

关键：同一套日期选择器出现在所有入口，肌肉记忆只建立一次。

**④ 开始专注**

```
任务行左滑 → 「专注」→ 全屏计时页（任务名 + 环形进度）
退出：下拉通知栏可见剩余时间；点通知回到计时页
结束：完成 / 补时 5 分钟 / 修正时长
```

关键：全屏但不劫持系统；锁屏也能看到剩余时间。

**⑤ 打卡**

```
习惯卡片 → 点「完成」→ 格子填色 + 数字 +1 + 轻震动
漏打卡 → 长按那一天的格子 → 补卡（可填次数与备注）
```

关键：一屏能看到本周 7 格，连续天数紧邻当前格，不需要进二级页。

### 4.5 反馈与撤销

| 场景 | 视觉 | 触觉 | 声音 | 撤销 |
| --- | --- | --- | --- | --- |
| 完成任务 | 勾选 + 下沉淡出 | 轻 | 可选 | 3 秒 Snackbar |
| 打卡 | 格子填色 + 计数跳动 | 轻 | 可选 | 3 秒 |
| 删除任务 | 左滑移除 | 中 | 无 | 5 秒，放垃圾箱 |
| 专注结束 | 环形收束 + 统计卡 | 中 | 可选 | 可修正时长 |
| 保存失败 | 行内红字 | 错误 | 无 | 重试按钮 |

原则：**只有破坏性操作需要确认弹窗，其余一律"先做再撤销"**。确认弹窗是效率杀手。

### 4.6 通知与锁屏

| 场景 | 通知内容 | 按钮 |
| --- | --- | --- |
| 任务提醒 | 标题 + 清单名 + 时间 | 完成 / 稍后 1 小时 |
| 专注进行中 | 剩余 18:32 · 写周报 | 暂停 / 结束 |
| 专注结束 | 本次 25:00 · 写周报 | 记录 / 补时 |
| 每日回顾（可选） | 今天完成 5 项，还有 3 项待办 | 打开今日 |

点击通知一律进入对应任务详情，不做"打开首页再找"。

### 4.7 返回与状态恢复

- Android 物理返回：详情 → 列表 → Tab 根 → 再次返回提示"再按一次退出"。
- 从通知进入详情后，返回回到进入前的 Tab，而不是首页。
- 杀进程重启后恢复：上次 Tab、列表滚动位置、日历视图模式。
- 编辑中被打断（来电/切后台）：保留草稿，30 分钟内不丢。

### 4.8 空态、加载与错误

| 状态 | 处理 |
| --- | --- |
| 今日为空 | 一句"今天没有安排"，下方给「添加任务」与「看看最近 7 天」 |
| 清单为空 | 说明这个清单的用途 + 新建按钮 |
| 搜索无结果 | 显示搜索词 + "试试只搜标题" |
| 首次启动 | 不弹权限、不弹引导页；直接进今日，用一条示例任务示范勾选 |
| 加载 | 本地库读取 < 100 ms，不显示骨架屏，避免闪烁 |
| 出错 | 行内提示 + 重试，不用全屏错误页 |

### 4.10 搜索

搜索是仅次于勾选的高频动作，因此不做成"点图标再输入"，而是**常驻**。

| 项 | 规格 |
| --- | --- |
| 位置 | 标题下方、列表上方 |
| 高度 | 36 dp，圆角 9，底色比页面背景深一档 |
| 占位 | "搜索任务、备忘录" |
| 点击 | 进入全屏搜索页，键盘同步弹出 |
| 输入 | 防抖 200 ms 实时过滤，不清空原列表上下文 |
| 结果 | 分组：任务 / 备忘录 / 清单；每组最多 5 条 + "查看全部" |
| 空查询 | 最近搜索（≤5 条）+ 快捷筛选：今天 / 逾期 / 有提醒 / 无日期 |
| 返回 | 恢复原列表滚动位置，不重置 |
| 桌面 | 顶栏固定搜索框，`Ctrl+K` 聚焦 |

匹配范围：标题、备注、备忘录正文、清单名。默认模糊匹配，输入空格视为多词与（AND）。

### 4.11 设置页

设置页是**中枢**，不是开关堆。从上到下六段，每段"一行标题 + 若干入口"，最多两级：

| 区块 | 入口 | 说明 |
| --- | --- | --- |
| 我的内容 | 备忘录（数量）、已完成、回收站 | 回收站是重点，误删自救 |
| 导航栏 | 中间 Tab 勾选与排序、实时预览 | 今天与设置固定；最多 5 个（ADR-0014） |
| 视图 | 视图开关、默认视图、并排布局 | 开关按设备保存，大屏视图标注"适合大屏" |
| 外观 | 主题、字号、重要性配色、行内色条 | 配色含"色觉友好"主题 |
| 数据 | 备份与恢复、导出、占用空间 | 显示图片缓存占多少 |
| 开发者 | 日志查看、诊断信息、导出日志、清空缓存 | **默认折叠**，连点版本号 5 次才出现 |
| 关于 | 版本号 + 构建号、更新说明、开源许可、隐私政策 | 版本号可复制 |

**回收站规则**

- 删除任务/备忘录先进回收站（软删），列表不再显示。
- 保留 **30 天**，到期自动清理；设置页显示剩余天数。
- 回收站内每条支持"恢复"与"彻底删除"；批量清空需二次确认。
- 恢复时若原清单已删除，落回收件箱并提示。

**日志规则**

- 只记录应用事件与错误，不记录任务内容（隐私）。
- 内存环形缓冲 2000 条 + 落盘滚动文件（单个 ≤2 MB，最多 3 个）。
- 可按级别过滤（全部 / 警告 / 错误），支持一键导出为 txt 分享给开发者。
- 番茄计时、提醒调度、数据库迁移必须有日志埋点——这三个模块出问题时，日志是唯一线索。

### 4.12 全屏专注与横屏

专注模式可以进入全屏：隐藏状态栏、Tab 与搜索，屏幕常亮，只剩时间与任务。手机立在桌上时切横屏，字号按"一米外可读"重排。

**全屏布局**

| 方向 | 主视觉 | 次要信息 | 操作 |
| --- | --- | --- | --- |
| 竖屏 | 剩余时间（超大，居中） | 真实时间（左上）、共 25:00（下方）、任务名 | 暂停 / 结束，底部居中 |
| 横屏 | 剩余时间（左列 60%，更大） | 任务名、真实时间、预计结束（右列 40%） | 右列底部横排 |

**两类时间并存**：剩余时间每秒刷新、等宽数字；真实时间每 10 秒刷新（整分立即刷新）；下方给"预计 22:05 结束"。剩余最后一分钟才切到秒级——平时显示秒只会让人盯着看。

**退出**：右上角退出按钮（3 秒无操作淡出，点屏幕重现）、返回键、下滑手势。返回键只退全屏，不结束计时。

**专注中新任务**：自本次专注开始后新建、未完成的任务，会在底部（横屏为右列）出现一条低对比提示"专注中新加入 2 个任务"，展开显示最多 3 条。点开是半屏浮层：可就地勾选完成，也可进详情（离开专注但保留计时）。不弹窗、不响铃、不抢焦点；忽略后本次不再提示。

设置项：进入专注即全屏（默认关）、全屏常亮（默认开）、专注中显示新任务（默认开）。

### 4.13 不照搬滴答的四处

1. **不把清单藏进汉堡菜单做唯一入口**：滴答的侧边栏发现性差，新用户常找不到清单。我们在今日页顶部放"当前清单"可点切换。
2. **不让日历挤压任务列表**：滴答日历页信息密度过高。我们让日历只做"时间视角"，任务仍回列表处理。
3. **不做强制全屏的番茄**：滴答的专注页会打断一切。我们允许退出后后台计时。
4. **不设"收集箱不可删除"这类硬规则**：默认清单可改名可归档，降低心理负担。

## 5. 视图系统

参照插件把六种视图平铺在工具栏，手机上要横向滚动才能找全，而甘特、表格这类视图在 6 寸屏上基本不可用。我们的做法是：**视图是可裁剪的投影，不是功能清单**。

### 5.1 视图注册表

| 视图 | 适用域 | 手机默认 | 建议最小宽度 | 依赖字段 |
| --- | --- | --- | --- | --- |
| 清单 | 任务 / 备忘录 | ✅ | — | 无 |
| 日历 | 任务 | ✅ | — | 截止日期 |
| 四象限 | 任务 | ✅ | — | 重要性 + 截止日期 |
| 画廊（备忘录） | 备忘录 | ✅ | — | 无 |
| 表格 | 任务 | ❌ 大屏优先 | 900 dp | 无 |
| 看板 | 任务 | ❌ 大屏优先 | 840 dp | 状态/清单 |
| 时间轴 | 任务 | ❌ 大屏优先 | 1000 dp | 开始 + 截止 |
| 并排 | 任务 / 备忘录 | ❌ 仅桌面 | 1000 dp | — |

"手机默认 ❌"的视图**不出现在手机弹层里**，只列在设置中并标注"适合大屏，已在手机上隐藏"，可手动打开。避免"能点开但没法用"。

### 5.2 三个切换入口

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 快速切换 | 工具条视图图标 | 手机：底部弹层，2×3 磁贴，每个磁贴带缩略示意；桌面：分段控件直接可见 |
| 长按切换 | 长按视图图标 | 在最近两个视图之间往返（今天 ↔ 最近 7 天） |
| 设置开关 | 设置 → 视图 | 逐项开关，**按设备保存**，手机与桌面各自记忆 |

### 5.3 大屏并排

宽度 ≥1000 dp 时可开双栏：主视图 + 副视图，比例 3:2，分隔条可拖动。典型组合：

- 清单 + 日历（左边处理、右边看排期）
- 四象限 + 清单（先分类，再执行）
- 备忘录 + 任务详情（边查资料边改任务）

副视图可折叠，折叠后回到单栏。手机端不提供并排，避免信息密度失控。

### 5.4 状态记忆

三层，就近优先：

1. 每个域记住上次使用的视图（跨启动保留）；
2. 每个清单可单独指定默认视图（如"读书"清单固定看板）；
3. 可见性与并排布局按设备保存，不同步。

切换视图**不重置筛选与滚动位置**，视图只换呈现，不写库。

## 6. 备忘录

### 6.1 为什么不做成任务的备注

备注是任务的从属字段，用完即沉底。而真实场景里大量内容是"先有资料、后有任务"：会议记录、截图、网页链接、清单草稿。做成独立实体才能被复用、被检索、被多个任务引用。

### 6.2 三个实体与两种关联

| 实体 | 作用 |
| --- | --- |
| `notes` | 备忘录：标题、正文、颜色、置顶、归档 |
| `note_assets` | 图片与文件：本地路径、尺寸、大小 |
| `task_note_links` | 任务与备忘录的关联，带模式 |

两种关联模式，语义必须说清：

- **引用**（reference）：任务里看到的是一条备忘录卡片，点开编辑的是同一份内容；备忘录改了，所有引用它的任务同步。
- **快照**（inline）：把当时的内容复制进任务备注，之后互不影响，适合"把这段资料冻结在这次任务里"。

默认用引用，因为多数情况是"同一份资料服务多个任务"。

### 6.3 能放什么

| 类型 | 支持 | 限制 |
| --- | --- | --- |
| 文本 | Markdown 子集：标题、列表、引用、代码、粗斜体 | 不做表格与 HTML |
| 图片 | 插入、粘贴、拍照 | 长边压缩至 ≤1600 px，转 WebP，单张压缩后通常 <300 KB |
| 链接 | 粘贴自动识别为卡片（域名 + 标题） | **不抓正文**，离线只显示域名与图标；标题可手改 |
| 任务引用 | 插入任务标题作为链接 | 不复制任务内容 |

刻意不做网页正文抓取、PDF 解析、录音：它们引入网络依赖与解析复杂度，与"离线优先"直接冲突。

### 6.4 三个入口

1. **抽屉入口**：默认不占底部 Tab。设置中可把"备忘录"加入底部 Tab（最多 5 个）。
2. **任务详情 → 备忘录区块**：关联已有、就地新建、切换引用/快照。
3. **快速添加 → 添加备忘录**：写完直接建任务并关联（引用模式）。

反向路径：备忘录详情可"转为任务"，标题带过去，正文按引用关联。

### 6.5 存储与备份

- 图片存 `assets/notes/<note_id>/<uuid>.webp`，数据库只存相对路径。
- `notes_fts(title, body)` 参与全局搜索，结果与任务分组展示。
- 备份为 zip：`backup.json` + `assets/`；恢复时校验缺失附件并列出清单，不静默丢图。

### 6.6 呈现与排序

两种呈现，工具条上一个图标切换，长按在两者间往返：

| 呈现 | 适用 | 结构 |
| --- | --- | --- |
| 列表 | 找一条具体资料 | 40 dp 缩略图 + 标题 + 一行摘要 + 时间/关联数 |
| 卡片（网格） | 看素材、翻灵感 | 两列，图片优先，无图则纯文字，左下角显示重要性色条 |

排序四选一，置顶永远优先且不参与排序：

| 排序 | 说明 |
| --- | --- |
| 添加时间 | 默认，最新的在前 |
| 更新时间 | 近期改过的在前 |
| 重要性 | 高→低，同级按添加时间倒序 |
| 标题 | 按拼音/字母序 |

呈现方式与排序按域保存，跨启动保留。备忘录新增 `importance` 字段（0–3），复用 ADR-0012 的四色语义；列表与卡片上的色条、详情页的色点，与任务完全一致。

### 6.7 生命周期

删除被引用的备忘录时，先提示"3 个任务正在引用"；确认后关联置空，任务本身不删。硬删后其附件进入待清理队列，启动时清理。

## 7. 重要性色彩与四象限

### 7.1 一套色板，只表达重要性

| 重要性 | 语义 | 主色 | 底色 |
| --- | --- | --- | --- |
| 高 | 必做，影响结果 | `#C2333A` | `#FCEBEB` |
| 中 | 应该做，有期限 | `#B45309` | `#FAEEDA` |
| 低 | 有空再做 | `#185FA5` | `#E6F1FB` |
| 无 | 未评估 | `#6B7280` | `#F3F4F6` |

出现位置（语义完全一致）：

1. 任务行左侧 **3 px 色条**（不整行染色，避免界面变花）；
2. 复选框描边（有重要性时用主色，完成后转灰）；
3. 详情页重要性 chip 的底色与文字。

### 7.2 四象限是算出来的，不是另设字段

```
纵轴 = 重要性：高/中 → 上（重要）；低/无 → 下（不重要）
横轴 = 紧急度：截止 ≤3 天 或 已逾期 → 右（紧急）；其余 → 左
```

| 象限 | 条件 | 底色 | 名称 |
| --- | --- | --- | --- |
| Q1 | 重要 + 紧急 | 红 6% | 马上做 |
| Q2 | 重要 + 不紧急 | 琥珀 6% | 计划做 |
| Q3 | 不重要 + 紧急 | 蓝 6% | 尽快脱手 |
| Q4 | 不重要 + 不紧急 | 灰 4% | 有空再说 |

约定：**象限底色表达"这个格子意味着什么"，卡片色条仍表达"这张卡自身的重要性"**。混入不同重要性时两者会不一致，这是有意的，不强行统一。

### 7.3 创建时的选择方式

不用下拉：快速添加与详情页都放**一行四个色点**（高/中/低/无），点选即生效，选中态有描边与文字。下拉需要两次点击还会遮住键盘。

### 7.4 不只靠颜色

- 详情页有文字（"高 / 中 / 低 / 无"），屏幕阅读器朗读"重要性：高"。
- 四象限每格有标题与数量。
- 日历任务块用左侧色条 + 文字，不整块填色。
- 提供**色觉友好主题**：高改品红 `#A21CAF`、低改青 `#0F6E56`，只换 token 不改数据。

首次使用给一句说明文字：

> 颜色代表重要性：红=必做，琥珀=该做，蓝=有空做。四象限按重要性与截止时间自动排布。
