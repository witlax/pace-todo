# 09 · 交互完善方案（v0.7 目标）

> 状态：设计定稿，待开发
> 基线：0.6.0（commit d671ae5）
> 预览：`preview/v1-full-preview.html`（39 屏，单文件，可直接浏览器打开）

## 1. 目标与边界

这一轮**不增加功能类别**。范围仍以 Pinch 的核心能力为界：
任务 / 清单 / 视图（工作台·日历·看板）/ 习惯 / 备忘录 / 专注 / 设置。

要解决的问题只有一个：**已有功能不够顺手**。判断标准是三条可量化的：
少一次点击、少一次犹豫、少一次误操作。不满足的不做。

参照三家产品的操作逻辑，只取与这四条主路径相关的部分：

| 参照 | 取什么 | 不取什么 |
| --- | --- | --- |
| 滴答清单 | 一句话录入 + 解析、右滑设今天、长按菜单、排期面板、完成后下沉、清单摘要、搜索语法 | 多级清单、日历订阅、协作与指派、番茄白噪音 |
| 朝暮计划 | 计划—打卡—复盘闭环、月历点日期看当天、打卡月历与连续天数、按天回顾 | 情绪/天气记录、每日强制复盘、社交打卡 |
| 指尖时光 | 专注与任务绑定、全屏沉浸、计时结算、专注统计 | 白噪音库、小组件生态、会员体系 |

## 2. 六条全局规则

1. **手势有等价入口**：左滑归档/删除、右滑排期、长按菜单，三者都另有可视入口，不依赖手势才能完成操作。
2. **破坏性操作可逆**：完成/归档给 4 秒撤销；删除进回收站保留 30 天；清空与覆盖恢复二次确认并写明后果。
3. **时间到分钟，"全天"是显式选项**；日期（什么时候做）与提醒（什么时候叫我）分开，提醒默认跟随日期平移。
4. **颜色只表示重要性**（高/中/低/无），分类一律用标签，避免"红=紧急又=工作"的语义打架。
5. **完成态留在列表**：变灰 + 删除线 + 完成时间，有总结标一句，可撤销。
6. **一个动作一个主入口**：点整行进详情、点圆圈完成、点箭头展子任务；次要动作收进长按或"更多"。

## 4. 逐屏对照

`preview/v1-full-preview.html` 第「十」节列出 39 屏及状态，这里只记差异类型：

- **仅调整交互**（不动 schema）：今天清单、快速添加、详情、清单、日历、习惯全部、搜索、设置、桌面。
- **需要新组件**：排期面板、专注胶囊、结算页、空态示例。
- **需要数据支持**：备份 zip（无 schema 变更）、清单手动排序（`tasks.sortOrder` 已存在，仅需启用）、看板拖拽（复用 `status`）。

**不需要 schema 升级**——这是本轮刻意控制的结果：v4 的字段已够用，交互问题不该靠改表解决。

## 5. 开发顺序与验收

### 第一轮（0.7.0）

排期面板 → 详情重排 → 打卡改造 → 专注保活 + 胶囊 → 快速添加解析。

验收：
- 新建一条带时间的任务 ≤ 2 次点击（不含输入标题）；
- 打卡 ≤ 1 次点击，撤销 ≤ 1 次点击；
- 切后台 10 分钟，专注计时误差 < 1 秒；
- 详情页首屏能看到子任务与备注。

### 第二轮（0.8.0）

右滑排期 + 长按菜单 → 月历内联议程 + 周视图任务块 → 看板拖拽 → 专注结算 → 搜索语法 → 备份 zip。

验收：
- 三个高频动作（排期、完成、打卡）都能不看说明完成；
- 换机恢复后附件可打开；
- 看板拖拽后在今日列表状态一致。

### 第三轮（0.9.0）

四象限拖拽、清单手动排序、桌面快捷键与两栏自适应、空态示例、动效与无障碍。

验收：
- 桌面端全流程仅用键盘可完成；
- 100% 交互元素有语义标签；
- 深色模式对比度 ≥ 4.5:1。

## 6. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 自然语言解析误判 | 用户存错日期 | chip 可点开修正；解析失败不报错、不阻塞输入 |
| 打卡取消确认后误触 | 脏数据 | 4 秒撤销 + 日志可删；设置可开回二次确认 |
| 前台服务耗电/被杀 | 计时中断 | 常驻通知可暂停；启动时校验上次会话并给出"补记"选项 |
| 排期面板改动面大 | 回归风险 | 单一组件 + 四处接入，先替换新建页，再替换详情与日历 |
| 备份 zip 兼容 | 旧 JSON 无法导入 | 保留 JSON 导入通道，新格式另存扩展名 |
