# ADR-0012 重要性色彩体系与四象限的统一映射

- 状态：已接受
- 日期：2026-11-19
- 关联：`docs/05` 第 7 节

## 背景

参照产品里，"优先级"和"四象限"常常是两套互不相干的视觉：列表用旗标或文字，四象限用另一套色块。用户需要记两遍规则，切换视图时认知断裂。

需求明确要求：添加任务时用颜色区分重要性，且四象限要能对应上。

## 决策

### 1. 一套色板，只表达"重要性"

| 重要性 | 语义 | 主色（浅色主题） | 底色 | 深色主题主色 |
| --- | --- | --- | --- | --- |
| 高 | 必做，影响结果 | `#C2333A` | `#FCEBEB` | `#F09595` |
| 中 | 应该做，有期限 | `#B45309` | `#FAEEDA` | `#EF9F27` |
| 低 | 有空再做 | `#185FA5` | `#E6F1FB` | `#85B7EB` |
| 无 | 未评估 | `#6B7280` | `#F3F4F6` | `#9CA3AF` |

颜色出现在三处，语义完全一致：

1. **任务行左侧 3 px 色条**（不做整行染色，避免界面噪杂）。
2. **复选框描边**：有重要性时用主色，完成为灰。
3. **详情页重要性 chip** 的底与文字色。

### 2. 四象限由两个轴计算，而不是另设字段

```
纵轴 = 重要性：高 / 中 → 上（重要）；低 / 无 → 下（不重要）
横轴 = 紧急度：截止 ≤ 3 天 或 已逾期 → 右（紧急）；其余 → 左
```

| 象限 | 条件 | 底色 | 名称 |
| --- | --- | --- | --- |
| Q1 | 重要 + 紧急 | 红 6% | 马上做 |
| Q2 | 重要 + 不紧急 | 琥珀 6% | 计划做 |
| Q3 | 不重要 + 紧急 | 蓝 6% | 尽快脱手 |
| Q4 | 不重要 + 不紧急 | 灰 4% | 有空再说 |

关键约定：**象限底色表达"这个格子意味着什么"，卡片色条仍然表达"这张卡自身的重要性"**。因此混入不同重要性的任务时，色条与底色会不同——这是有意的，不强行统一。

### 3. 颜色不是唯一信息载体

- 列表行除色条外，详情页有文字（"高 / 中 / 低 / 无"）。
- 四象限每格有标题与数量，不靠颜色区分。
- 日历中的任务块用左侧色条 + 文字，不用整块填色。
- 屏幕阅读器朗读"重要性：高"，不读颜色。

### 4. 色觉友好主题（可切换）

默认色板对红绿色弱不友好（红与琥珀在小面积上易混）。提供第二套：

| 重要性 | 色觉友好主色 | 依据 |
| --- | --- | --- |
| 高 | `#A21CAF`（品红） | 与琥珀在 deutan 模拟下色相差足够 |
| 中 | `#B45309`（琥珀） | 保留 |
| 低 | `#0F6E56`（青） | 与品红、琥珀均可区分 |
| 无 | `#6B7280` | 中性 |

设置在"外观 → 重要性配色"中切换，只影响前端 token，不影响数据。

### 5. 创建任务时的选择方式

不用下拉框：快速添加弹层与详情页都放**一行四个色点**（高/中/低/无），点选即生效，选中态有描边与文字。理由：下拉需要两次点击且遮住键盘。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 优先级与四象限各用一套颜色 | 认知负担翻倍，切换视图要重新理解 |
| 整行按重要性染色 | 列表变成色块拼贴，扫读标题困难 |
| 只用图标（旗标/星标）不用颜色 | 手机上小图标辨识度低，扫视效率差 |
| 让用户完全自定义每级颜色 | 配置成本高，且破坏"一处学会、处处适用" |

## 后果

正向：

- 用户只需记住一条规则："红=重要且急，琥珀=重要但不急，蓝=不重要但急，灰=都不"。
- 列表、日历、四象限、看板共用一套 token，新增视图自动一致。
- 色觉友好主题成本低（只换色值）。

负向：

- 红色在中文语境中也可能被理解为"超期"，需要在首次使用时用一句话说明（见下）。
- 三档重要性对某些用户过粗，未来可能需要五档，届时色板要扩充。
- 四象限的 3 天阈值是固定规则，用户可能想调整（V1.1 开放设置）。

## 首次使用说明文案

> 颜色代表重要性：红=必做，琥珀=该做，蓝=有空做。四象限按重要性与截止时间自动排布。

## 重新评估条件

1. 用户调研显示"红=超期"的误解率 > 30%，则改用紫/橙体系；
2. 需要支持五档重要性；
3. 引入自定义主题系统，色板需改为可注入的设计令牌。
