# ADR-0014 底部导航可配置；专注上移首页；备忘录支持列表/卡片与排序

- 状态：已接受
- 日期：2026-11-19
- 关系：取代 ADR-0013 中"5 个固定 Tab"的部分；搜索栏与设置中枢的结论不变

## 背景

ADR-0013 把底部固定为 5 个：今天 / 日历 / 专注 / 习惯 / 设置。实际使用中有两个问题：

1. **专注不是"域"，是"模式"**：它没有独立的数据集合，只有一段正在进行的计时。给它一个常驻 Tab，等于让用户为了"看一个计时器"切走当前上下文。
2. **Tab 组合因人而异**：不用习惯的人，习惯 Tab 永远占位；把备忘录当主要收集箱的人，反而要绕道设置页。

## 决策

### 1. 底部导航可配置，但保留两个锚点

- **今天**固定在第一位（首页，不可移除）。
- **设置**固定在最后一位（不可移除）。
- 中间最多 3 个位置，从 `日历 / 习惯 / 备忘录` 中勾选，可拖动排序。
- 上限 5 个；少于 1 个中间项时允许（即 今天 + 设置 两个）。
- 默认：`今天 / 日历 / 习惯 / 设置`（4 个）。

配置入口：设置 → 导航栏。页面上有实时预览条（可直接拖动排序），并提示"今天与设置固定显示"。

### 2. 专注从 Tab 移到首页，作为并列模式

- 今天页顶部（搜索栏上方）放分段控件：**任务 / 专注**。
- 切到"专注"时：隐藏搜索栏与任务列表，显示计时环、当前任务、开始/暂停。
- 有计时在跑时，任意页面底部（Tab 栏上方）显示一条 **18 dp 的运行条**："专注中 18:32 · 写周报"，点击回到计时页。
- 任务行左滑的"专注"与详情的"开始专注"仍然保留，作为带上下文的入口。
- 桌面端：左侧导航仍列出"专注"，因为大屏没有"首页模式"的概念，且空间充足。

理由：专注是"进入一种状态"，不是"去到另一个地方"。放在首页顶部，切换成本从一次 Tab 跳转变成一次轻点，且不会丢失任务上下文。

### 3. 备忘录支持两种呈现与四种排序

- 视图：**列表**（行式，含 40 dp 缩略图）与**卡片/网格**（两列，图片优先）。工具条上一个图标直接切换，长按在两者间往返（与任务视图规则一致）。
- 排序：**添加时间 / 更新时间 / 重要性 / 标题**；置顶永远优先，不参与排序。
- 排序与呈现按域保存，切换后跨启动保留。
- 备忘录新增 `importance` 字段（0–3），复用 ADR-0012 的四色语义，用于排序与色条。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 保持 5 个固定 Tab | 与个人使用习惯强绑定，必然有人用不上 |
| 全部 Tab 可增删（含今天/设置） | 移除首页或设置会导致迷路，恢复路径难找 |
| 专注保留 Tab，同时首页也放入口 | 两处入口、两套状态，容易不一致 |
| 专注改为 FAB 长按菜单 | 发现性差，且与"新建"冲突 |
| 备忘录只做一种视图 | 收集箱偏列表、素材偏卡片，需求分裂 |

## 后果

正向：

- 界面按个人习惯裁剪，习惯与备忘录的取舍由用户决定。
- 专注不再打断导航，任务上下文保留。
- 备忘录的两种呈现覆盖"找一条"与"看素材"两类场景。

负向：

- Tab 配置增加状态与校验（至少 1 个、至多 3 个中间项），设置页逻辑变复杂。
- 专注入口分散在三处（首页模式、左滑、详情），需要统一状态源，否则易出现"两个计时器"。
- 备忘录增加 `importance` 字段，需要一次 schema 迁移。

## 重新评估条件

1. 超过 30% 的用户把中间项全部关闭（只剩今天+设置），说明 Tab 机制本身价值不足，考虑改为单页 + 抽屉；
2. 专注运行条在非专注页造成遮挡投诉；
3. 备忘录网格视图使用率低于 10%，则移除，仅保留列表。
