# ADR-0010 视图系统：注册表 + 快速切换 + 按设备控制可见性

- 状态：已接受
- 日期：2026-11-19
- 关联：`docs/05` 第 5 节

## 背景

参照插件提供了大量视图：Pinch 有清单/表格/看板/日历/甘特，Task Horizon 有清单/表格/时间轴/看板/日历/白板/仪表盘。但它们把所有视图平铺在同一层工具栏，手机上横向滚动才能找全，且多数视图在小屏上体验很差（甘特、表格、白板在 6 寸屏上几乎不可用）。

同时，不同视图的价值取决于屏幕：手机上"清单 + 日历"足够，桌面才需要表格、时间轴、并排对照。全部显示会挤爆手机，全部隐藏又浪费大屏。

## 决策

### 1. 视图以注册表描述，不硬编码进页面

```dart
class ViewDescriptor {
  final String id;            // checklist / table / board / quadrants / timeline / calendar / gallery
  final Set<Domain> domains;  // tasks / habits / memos
  final bool mobileCapable;   // 手机是否默认可选
  final int minWidth;         // 建议最小宽度（dp），低于则提示
  final Set<Field> requires;  // 依赖字段（如日期）
  final bool defaultEnabled;
}
```

新增视图只需注册一条描述，工具条、设置项、并排视图的候选列表自动更新。

### 2. 三个入口，各解决一类场景

| 入口 | 交互 | 解决什么 |
| --- | --- | --- |
| 工具条快速切换 | 手机：点视图图标 → 底部弹层 2×3 视图磁贴（带缩略示意 + 是否"大屏优先"）；桌面：分段控件直接可见 | 主动换视角 |
| 长按视图图标 | 在最近两个视图之间来回切 | 高频对照（今天↔最近 7 天） |
| 设置 → 视图 | 逐项开关，按设备独立保存 | 去掉用不上的视图，减少误触 |

### 3. 大屏优先视图默认不在手机出现

标记为 `mobileCapable=false` 的视图（表格、时间轴、看板、并排）在手机上**不进入弹层**，只在设置中列出，并标注"适合大屏，已在手机上隐藏"，可手动开启。避免"能点但难用"。

### 4. 大屏并排视图（≥1000 dp）

- 主视图 + 副视图双栏，宽度比 3:2，可拖动分隔条。
- 典型组合：清单 + 日历、四象限 + 清单、备忘录 + 任务详情。
- 副视图可折叠，折叠后回到单栏。

### 5. 状态记忆（三层，就近优先）

1. 每个域记住"上次使用的视图"（跨启动保留）。
2. 每个清单可单独指定默认视图（如"读书"清单固定看板）。
3. 视图可见性与并排布局**按设备保存**，不同步（手机与桌面需求天然不同）。

切换视图不重置筛选与滚动位置；视图只是数据的投影，不写库。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 所有视图平铺工具栏（参照插件做法） | 手机上需要横向滚动，发现性差 |
| 按屏幕宽度强制不同视图 | 用户无法选择，且横竖屏切换时跳变 |
| 每个清单固定一个视图 | 灵活度不足，跨清单对照困难 |
| 视图做成独立页面 | 切换成本高，失去"同一份数据换视角"的意义 |

## 后果

正向：

- 手机端界面干净，桌面端能力完整，同一套代码用断点与注册表分流。
- 新增视图成本低（注册 + 一个 Widget），不影响导航结构。
- 用户可按习惯裁剪，减少"功能很多但都不顺手"的问题。

负向：

- 视图状态需要按设备持久化，比全局单例复杂。
- 并排视图增加布局与手势冲突的处理成本（尤其拖拽分隔条与列表滚动）。
- 设置项增多，需要合理的默认值，否则用户面对一堆开关。

## 重新评估条件

1. 手机端用户调研显示 80% 以上只用清单，可进一步砍掉弹层；
2. 并排视图的使用率长期低于 5%，则移除，只保留单视图；
3. 平板成为主要目标设备，需要重新定义断点与默认可见集。
