# ADR-0011 备忘录作为一等实体，与任务多对多关联

- 状态：已接受
- 日期：2026-11-19
- 关联：`docs/05` 第 6 节

## 背景

现有产品里"备注"只是任务的一个字段（Markdown 文本）。但真实使用中，很多内容是**先有资料、后有任务**：一段会议记录、一张截图、一个网页链接、一份清单草稿。把它们硬塞进某一任务的备注，会导致：

- 同一份资料被复制到多个任务，改一处不同步；
- 资料没有独立入口，找不到、搜不到；
- 任务完成后资料随之"沉底"，无法复用。

因此需要一个独立的"备忘录"实体，并能与任务建立关联。

## 决策

### 1. 三个实体

```sql
notes(id, title, body_md, color, pinned, archived,
      created_at, updated_at, deleted_at, rev, device_id)

note_assets(id, note_id, type,          -- image | file
            local_path, mime, width, height, size,
            created_at, deleted_at)

task_note_links(task_id, note_id, mode, sort_order, created_at)
-- mode: reference（引用，改备忘录即同步）| inline（快照，独立）
```

- `reference`：任务详情显示备忘录卡片，点开编辑的是同一份内容。
- `inline`：把当时的内容复制进任务备注区，之后互不影响（适合"把这段资料冻结在这次任务里"）。

### 2. 内容能力（V1 范围）

| 类型 | 能力 | 限制 |
| --- | --- | --- |
| 文本 | Markdown 子集：标题、列表、引用、代码、粗斜体 | 不做表格与 HTML |
| 图片 | 插入、粘贴、拍照；压缩至长边 ≤1600 px，转 WebP | 单张 ≤5 MB（压缩后通常 <300 KB） |
| 链接 | 粘贴自动识别为卡片：域名 + 标题 | **不抓正文**；标题可手动改，离线只显示域名与图标 |
| 任务引用 | 插入任务标题作为链接，点击跳转 | 不复制任务内容 |

刻意不做：网页正文抓取、PDF 解析、录音。它们会引入网络依赖与解析复杂度，与"离线优先"冲突。

### 3. 入口

- **抽屉默认入口**（不占底部 Tab）。设置中可把"备忘录"加入底部 Tab，上限 5 个。
- 任务详情的"备忘录"区块：可关联已有、可新建、可切换引用/快照。
- 快速添加时，输入框下方增加"添加备忘录"入口，写完直接建任务并关联（引用模式）。
- 备忘录详情可"转为任务"：标题带过去，正文按引用关联。

### 4. 存储与检索

- 图片存应用私有目录 `assets/notes/<note_id>/<uuid>.webp`，数据库只存相对路径。
- `notes_fts(title, body)` 参与全局搜索，与任务结果混合展示并分组。
- 备份：JSON + assets 目录打包为 zip；恢复时校验缺失附件并列出清单。

### 5. 生命周期

- 删除备忘录：若有 `reference` 关联，先提示"3 个任务正在引用"；确认后关联置空（任务本身不删）。
- 孤立附件清理：备忘录彻底删除（硬删）后，其 assets 进入待清理队列，启动时清理。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 备忘录 = 任务的备注字段 | 无法复用、无法独立检索、一改多份不同步 |
| 用附件挂到任务上 | 附件无语义、无标题、无法独立浏览 |
| 双向链接 / 块引用（类 Roam） | 概念复杂，单人工具收益低，工期翻倍 |
| 独立 KV 存储（如 Hive 单表） | 无法与任务做关联查询与全文检索 |

## 后果

正向：

- 资料与任务分离，同一份资料可被多个任务引用，改一处全局生效。
- 备忘录有独立入口与检索，符合"先收集、后整理"的真实习惯。
- 未来可自然扩展为"项目资料库"，无需改模型。

负向：

- 多两张表与关联表，备份与迁移复杂度上升。
- 图片存储带来体积增长，需要压缩策略与孤立文件清理。
- "引用 vs 快照"两种模式需要在 UI 上说清楚，否则用户困惑。

## 重新评估条件

1. 实际使用中引用模式占比低于 10%，说明用户只需要"快照"，可简化；
2. 需要跨设备同步图片，届时附件存储需改为可寻址对象存储；
3. 备忘录数量级进入数千，需要引入分页与索引优化。
