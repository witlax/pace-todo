# ADR-0013 底部导航扩为 5 个域，设置页承担中枢；清单页常驻搜索栏

- 状态：已接受
- 日期：2026-11-19
- 关联：ADR-0010（视图系统）、`docs/05` 第 4 节

## 背景

原设计是 4 个 Tab（今天/日历/专注/习惯）+ 抽屉，设置、回收站、视图开关都藏在抽屉里。实际使用中这会带来三个问题：

1. **视图开关找不到**：用户想关掉用不上的视图，得先想到"设置"，再找到"视图"，路径深。
2. **回收站无入口**：误删后无法自救，只能去设置深处翻。
3. **搜索摩擦高**：搜索是个图标，要先点开再输入；而搜索是任务管理里第二高频的动作（第一是勾选）。

同时，开发者日志、版本信息、外观这些"低频但必须存在"的入口也需要一个明确的家。

## 决策

### 1. 底部导航 5 个：今天 / 日历 / 专注 / 习惯 / 设置

- 顺序固定，不随使用频率自动排序（位置记忆比"智能"更重要）。
- 第 5 个命名为**设置**，图标用滑杆而非齿轮（齿轮在中文语境里更像"系统设置"，滑杆更像"偏好"）。
- 备忘录**不占 Tab**：入口在设置页顶部的"我的内容"区，以及抽屉。原因：备忘录是"查资料"而非"每天处理"的域，占一个常驻 Tab 会稀释主线。

### 2. 设置页是中枢，不是一堆开关的堆叠

从上到下六段，每段都是"一行标题 + 若干入口"，不超过两级：

| 区块 | 内容 |
| --- | --- |
| 我的内容 | 备忘录（12）、已完成、**回收站**（含 30 天保留说明） |
| 视图 | 视图开关（手机/桌面分别保存）、默认视图、并排布局 |
| 外观 | 主题（跟随系统/浅/深）、字号、重要性配色（默认/色觉友好）、行内色条开关 |
| 数据 | 备份与恢复、导出、占用空间 |
| 开发者 | 日志查看（按级别过滤）、诊断信息、导出日志、清空缓存 |
| 关于 | 版本号 + 构建号、更新说明、开源许可、隐私政策 |

"开发者"默认折叠，连续点击版本号 5 次才显示入口——普通用户不该看到日志。

### 3. 清单页常驻搜索栏

- 位置：标题下方，列表上方，高 36 dp，圆角 9，底色略深于背景。
- 占位文案："搜索任务、备忘录"。
- 点击进入全屏搜索页，键盘同时弹出；输入即过滤（防抖 200 ms），不清空列表上下文。
- 结果分组：任务 / 备忘录 / 清单，每组最多 5 条 + "查看全部"。
- 空查询时显示：最近搜索（最多 5 条）+ 快捷筛选（今天 / 逾期 / 有提醒 / 无日期）。
- 返回时恢复原列表位置，不重置滚动。

桌面端不重复放：搜索固定在顶栏，宽度 240–320 dp，`Ctrl+K` 聚焦。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 保持 4 Tab，设置放头像（滴答做法） | 设置发现性差，回收站几乎无人找到 |
| 6 Tab（再加备忘录） | 图标过密，触控区小于 48 dp，误触率高 |
| 第 5 个用"更多"聚合 | 多一层跳转，且"更多"是垃圾桶式命名 |
| 搜索仅保留图标 | 高频动作多一次点击，且无最近搜索可复用 |
| 搜索栏随滚动隐藏 | 滚动中想搜要先回顶，违背使用场景 |

## 后果

正向：

- 视图开关、回收站、日志、版本都在两步内可达。
- 搜索从"点图标"变成"直接输入"，高频路径缩短一次点击。
- 设置页结构固定，新增设置项只需挂到对应区块，不再随意堆叠。

负向：

- 5 个 Tab 在小屏（≤5.5"）上每个仅约 52 dp 宽，标签文字需缩到 9–10 sp。
- 设置页承载"我的内容"后职责略杂，需要靠分组标题维持秩序。
- 备忘录入口变深，若使用频率高，会需要再评估（见重新评估条件）。

## 重新评估条件

1. 备忘录周打开次数超过任务页的 30% → 允许用户把备忘录加入 Tab（上限 5，替换设置或习惯）；
2. 小屏设备上 Tab 标签出现截断 → 改为"图标 + 选中态文字"的混合模式；
3. 设置页条目超过 24 条 → 拆出二级"全部设置"页。
