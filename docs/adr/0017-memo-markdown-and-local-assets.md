# ADR-0017 备忘录采用 Markdown 源文件与本地附件目录

- 日期：2026-11-20
- 状态：已接受
- 影响范围：备忘录编辑页、note_assets 表的使用方式、备份格式

## 背景

用户要求备忘录支持图片、网络链接，并最好支持 Markdown，参考了 Monica 应用的编辑形态（编辑/预览切换、格式工具条、附件区）。

## 备选方案

1. **富文本（如 flutter_quill）**：所见即所得，但内容存为私有 JSON，导出、全文搜索、跨端都要额外处理；用户换了应用内容就带不走。
2. **Markdown 源文件 + 预览**：内容是纯文本，任何编辑器都能打开；预览用 flutter_markdown_plus 渲染；代价是没有所见即所得。

## 决策

选方案 2，理由：本地优先的产品承诺里，「数据永远是你的」排在「编辑体验华丽」之前。工具条保留——它做的是「插入标记」，降低 Markdown 语法记忆成本，而不是隐藏源文件。

附件：图片复制进应用文档目录 `note-assets/`，数据库只存相对路径与元数据。复制而非引用，是因为相册临时路径随时可能被系统回收。备份只导出数据库记录，图片文件随目录整体拷贝（备份页提示里已说明）。

标签：`notes.tags` 存逗号分隔文本，不建关联表。任务标签需要统计与筛选，所以是多对多；备忘录标签只是检索辅助，文本够用，且避免一次迁移引入两张表。

链接：预览中可点，但 V1 未接 `url_launcher`，行为是显示地址。宁可让用户复制，也不做一个「点了没反应」的假链接。

## 后果

- `schemaVersion` 2 → 3，`notes` 加 `tags` 列；
- 依赖新增 `flutter_markdown_plus`、`image_picker`、`path`；
- 备份恢复时若 `note-assets/` 目录缺失，图片显示为占位图，备份页应提示用户连同目录一起备份（TODO：备份页增加图片目录打包）。
