# ADR-0016 完成态留在列表、右滑动作与独立提醒字段

- 日期：2026-11-20
- 状态：已接受
- 影响范围：任务列表交互、任务表结构（schema v2）、通知调度

## 背景

0.2.0 的三处行为在真实使用中暴露出问题：

1. 任务完成后立刻从列表消失，用户无法确认「刚才那条到底完成没有」，也看不到完成时间；
2. 删除只能靠长按且直接进回收站，容易误删，想「先放一边」只能删或改日期；
3. 到期时间只有一个字段，既当排期又当提醒，且时间只能选到整点（默认 18:00），无法精确到分钟。

## 决策

### 1. 完成的任务留在列表，变灰显示

- 今日页新增「今日完成」分组，展示当天完成的任务；
- 样式：勾选圆点填充、标题删除线 + 变灰、副行显示「完成于 HH:mm」；
- 点圆圈即撤销完成，任务回到未完成分组；
- 详情页可写「完成总结」，列表里显示前两行。

理由：完成动作需要**即时反馈**，且完成总结是复盘的唯一素材。直接消失既没有反馈，也丢掉了「这次怎么做的」这一信息。

### 2. 删除改为右滑动作面板

- 右滑（startToEnd）弹出面板，提供「归档」与「删除」两项，附后果说明；
- 取消长按删除；
- 归档：写 `archivedAt`，移出列表，保留在「设置 → 归档」，可取消归档；
- 删除：进回收站，30 天可恢复。

理由：右滑是移动端删除的通用手势，且一次滑动能同时容纳两个语义不同的动作；长按既不可发现，也无法区分「删掉」与「先放一边」。

### 3. 提醒从到期时间中独立出来

- 新增 `tasks.remindAt`：为空表示按到期时间提醒；
- 提醒支持：准时、提前 10 分钟、提前 1 小时、自定义时刻、不提醒；
- 到期时间支持精确到分钟（选日 + 选时分两步）；
- 通知调度取 `remindAt ?? dueAt`。

理由：排期是「什么时候做」，提醒是「什么时候叫我」。两者常不一致（例如 18:00 到期，17:30 提醒），一个字段表达不了。精确到分钟是提醒可用的前提——整点提醒在实际使用中几乎没用。

## 迁移

`schemaVersion` 由 1 升至 2，`onUpgrade` 增加三列：

```dart
if (from < 2) {
  await m.addColumn(tasks, tasks.completedSummary);
  await m.addColumn(tasks, tasks.remindAt);
  await m.addColumn(tasks, tasks.archivedAt);
}
```

三列均可空，旧数据无需回填；已完成任务没有总结时列表不显示摘要行。

## 后果

- 列表变长：完成的任务会占据当天列表空间，但只保留当天，次日归档到「已完成」页；
- 依赖手势：右滑动作在桌面端不可用，Windows 端需在后续补右键菜单或行内按钮；
- 通知通道不变，仅调度时刻改为 `remindAt ?? dueAt`，无需重新申请权限。
