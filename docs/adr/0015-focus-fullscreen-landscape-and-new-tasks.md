# ADR-0015 专注支持全屏与横屏，全屏显示真实时间与专注中新任务

- 状态：已接受
- 日期：2026-11-20
- 关联：ADR-0014（专注上移首页）、`docs/05` 第 4.12 节

## 背景

专注模式目前嵌在首页里，和任务列表共用一屏。真实使用中会出现三种需求：

1. **想彻底不被打断**：列表、Tab、搜索都在视野里，注意力会被拉走。
2. **把手机立在桌上当时钟**：番茄钟最常见的物理形态是横屏立在支架上，此时需要的是"一眼可读"的大字。
3. **专注时仍会想到事**：突然想起"还要取快递"，如果必须先退出专注才能记，用户往往选择不记，事后就忘了。

## 决策

### 1. 全屏专注

- 入口：专注模式右下角的全屏图标；或设置中"进入专注即全屏"（默认关）。
- 进入后隐藏状态栏、标题栏、Tab 栏与运行条，使用沉浸式（Android `immersiveSticky`；Windows 无边框全屏）。
- 屏幕常亮（`wakelock`）默认开启，可在专注设置里关闭。
- 退出：右上角退出按钮、返回键、或下滑手势。**返回键只退出全屏，不结束计时**，再按一次才退出专注模式。
- 退出按钮在 3 秒无操作后淡出，点屏幕任意位置重新出现——避免烧屏与误触，但退出路径始终可达。

### 2. 横竖屏两套布局

自动跟随系统旋转；全屏时右上角提供"旋转"按钮，可在系统锁定竖屏时强制切换（退出全屏后恢复系统设置）。

| 方向 | 布局 |
| --- | --- |
| 竖屏 | 单列居中：真实时间（左上）、剩余时间（超大）、总时长、任务名、暂停/结束、新任务条（底部） |
| 横屏 | 双列：左侧 60% 放剩余时间（更大字号）与按钮；右侧 40% 放任务名、真实时间、预计结束时间、新任务列表 |

横屏不是把竖屏拉伸：字号、间距、按钮位置都按"距离 1 米可读"重新排。最小可读字号 48 sp（剩余时间），任务名 16 sp。

### 3. 全屏显示两类时间

| 时间 | 位置 | 格式 | 说明 |
| --- | --- | --- | --- |
| 剩余时间 | 主视觉 | `18:32` | 等宽数字，每秒刷新 |
| 真实时间 | 左上/右上 | `21:47` | 当前时钟，每 10 秒刷新（整分时立即刷新） |
| 预计结束 | 真实时间下方 | `预计 22:05 结束` | now + 剩余，改时长时同步 |

不显示秒，避免"盯着秒数"加剧焦虑；剩余时间最后一分钟才切到秒级。

### 4. 专注中新增的任务

**定义**：自本次专注开始时刻起，新创建且未完成、未删除的任务。

**为什么要显示**：专注时冒出的想法如果没处放，要么打断专注去记，要么直接忘掉。给它一个不打断的落点，是"专注"能持续的前提。

**交互**：

- 底部（横屏为右列底部）出现一条低对比度的提示条："专注中新加入 2 个任务"，展开显示前 3 条标题与时间。
- 不自动弹窗、不响铃、不抢焦点；仅一次轻微触觉反馈。
- 点提示条展开半屏浮层：可勾选完成（就地，不离开专注）、可查看详情（会离开专注并保留计时）。
- 可整体忽略；忽略后本次专注不再提示，但任务仍在列表里。
- 设置中可关闭"专注中显示新任务"（默认开）。

**不显示**：专注期间被他人修改的任务（V1 无同步）、到期提醒（走通知，不进专注页）。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 只做全屏，不做横屏 | 立在桌上是最常见用法，竖屏大字在远处不可读 |
| 全屏只显示剩余时间 | 用户需要知道"现在几点、几点结束"，否则要退出看时间 |
| 专注中新任务弹窗提醒 | 直接打断专注，与产品目的相反 |
| 专注时禁止新建任务 | 迫使用户在"记住"和"专注"之间二选一，实际会丢事 |
| 横屏时旋转 90° 渲染竖屏界面 | 字体与触控区错位，且系统手势冲突 |

## 后果

正向：

- 专注有了"仪式感"与物理可用性（立在桌上、远处可读）。
- 新任务有落点，减少"怕忘事所以不敢专注"的心理成本。
- 两类时间并存，减少退出查看的次数。

负向：

- 需要维护两套布局与旋转状态，测试面扩大（横竖屏 × 字号 × 深浅色）。
- 强制旋转与系统设置存在冲突，需要正确恢复。
- 全屏下提示条若处理不当会变成干扰源，需要严格的视觉降噪。

## 重新评估条件

1. 全屏使用率低于 10%，说明用户更依赖列表上下文，可移除入口；
2. 横屏布局在平板上与并排视图冲突；
3. 专注中新任务提示被反馈为干扰，改为仅在结束时汇总。
