## 四、依赖：三处真实冲突与解法

| 冲突 | 现象 | 解法 |
| --- | --- | --- |
| 桌面插件要求 Flutter 3.50 | `window_manager 0.7.0`、`tray_manager 0.9.0`、`hotkey_manager 0.4.0` 均要求 Dart ^3.14 / Flutter ≥3.50，当前 3.47.7 无法解析 | 锁定 0.5.2 / 0.5.1 / 0.2.3（ADR-0008） |
| `sqlite3_flutter_libs` 已废弃 | 最新版为 `0.6.0+eol`，说明写"改用 sqlite3 3.x 原生资产" | 用 drift 2.31.0 + `sqlite3_flutter_libs` 0.5.42（ADR-0007） |
| 原生资产构建链断裂 | sqlite3 3.x 从 GitHub Releases 下载二进制（本机 502）；`nativeapi` 系插件需 `reg.exe` 定位 MSVC（本机被安全策略禁用） | 改用预编译库 + 无 nativeapi 的插件版本 |

### 最终锁定的版本差异（相对 `docs/02` 初版）

| 包 | 初版 | 实际采用 | 原因 |
| --- | --- | --- | --- |
| drift | 2.35.4 | **2.31.0** | 2.32+ 强制 sqlite3 3.x，触发 GitHub 下载 |
| drift_flutter | 0.3.1 | **0.2.8** | 同上 |
| sqlite3_flutter_libs | 未列 | **0.5.42** | 提供预编译库，Android 走 Maven AAR，Windows 从 sqlite.org 编译 |
| window_manager | 0.7.0 | **0.5.2** | 0.7 要求 Flutter 3.50，且 0.6+ 依赖 nativeapi |
| tray_manager | 0.9.0 | **0.5.1** | 同上 |
| hotkey_manager | 0.4.0 | **0.2.3** | 同上 |
| compileSdk | 36 | **37** | `flutter_local_notifications 23` 与 `androidx.core 1.19` 强制 |
| 脱糖 | 未启用 | **启用 + desugar_jdk_libs 2.1.5** | 通知插件强制要求 |

## 五、构建与运行时验证

### Android

```
flutter build apk --debug
→ √ app-debug.apk  165 MB  （178.1 秒，依赖已缓存）
```

- `compileSdk = 37`、`minSdk = 26`、`isCoreLibraryDesugaringEnabled = true`
- APK 内含三个 ABI 的 `libsqlite3.so`（1.5 MB/个），数据库随包发布，不依赖系统 SQLite
- 首次构建耗时 752 秒，主要成本是 `cnativeapi` 的 C++ 编译（约 150 个源文件 × 3 个 ABI）

### Windows

```
flutter build windows --debug
→ √ stackcheck.exe  （42.3 秒）
```

### 运行时（主机侧，无需真机）

| 测试 | 内容 | 结果 |
| --- | --- | --- |
| SQLite 加载 | `sqlite3_version()` | 通过 |
| FTS5 | 建虚拟表 + 中文检索 | 通过 |
| RRULE | `FREQ=DAILY;COUNT=3` 展开 3 次且日期正确 | 通过 |
| 时区 | `Asia/Shanghai` 可解析 | 通过 |

> 这一步证明"数据库能真正打开并检索"，而不是"能编译"。编译通过但运行时找不到动态库，是 Flutter 原生依赖最常见的坑。

    compileSdk = 37
