## 2. 阶段定义

### M0 · 骨架与地基（1 周）

**目标**：把"能构建、能存数据、能留痕"一次性做对。

**范围**

- `app/` Flutter 工程：`applicationId=com.witlax.tasktodo`，Android + Windows
- 按 ADR-0007/0008 锁依赖；`compileSdk 37`、`minSdk 26`、脱糖、Gradle 镜像
- Drift 表结构与 `schemaVersion=1`（含 notes / note_assets / task_note_links，先建表不实现）
- 四个抽象：`Clock`、`TaskRepository`、`ReminderScheduler`（接口）、`RecurrenceService`（接口）
- 路由、主题令牌（含重要性色板）、深浅色、中英 ARB
- 日志与 `AuditLog` 骨架
- 质量门禁脚本

**验收标准**

1. 双端 `build --debug` 成功
2. 空库冷启动 < 1.5 s（中端机）
3. 迁移在"删库重装"与"递增版本"两条路径正确
4. 缺 DEVLOG 的依赖改动被钩子拒绝
5. 字号 1.3 倍无溢出；重要性四色在深色主题对比度 ≥ 4.5:1

---

### M1 · 任务核心与视图（4 周）

**目标**：让"记一条、找到一个、换个角度看"完整可用。

**范围**

- 任务 CRUD：标题、备注、重要性、开始/截止、预计时长
- 清单（含收件箱）、标签、单层子任务
- 智能清单：今天 / 最近 7 天 / 收件箱 / 已完成 / 逾期
- FTS5 搜索
- 手势：左滑完成/延期/专注，右滑置顶，长按拖拽
- 快速添加 + 日期快捷条 + **一行四色重要性选择**
- 完成反馈与 3 秒撤销
- **视图注册表 + 快速切换弹层 + 设置可见性**（ADR-0010）
- **四象限视图**（ADR-0012）
- **常驻搜索栏 + 全屏搜索页**（分组结果、最近搜索）
- **设置页骨架**：我的内容 / 导航栏配置 / 视图开关 / 回收站（30 天）/ 外观入口
- **首页模式切换**：任务 / 专注（专注不再占 Tab，含运行条）

**验收标准**

1. 5000 条任务滚动 60 fps；搜索 < 200 ms
2. 字段修改局部刷新，无整页闪烁
3. 快速添加 ≤3 次操作、≤3 秒
4. 视图切换后筛选与滚动位置不丢；长按可在最近两视图往返
5. 大屏优先视图在手机弹层中不出现，设置中可见并可开启
6. 四象限分桶正确：重要/紧急四组合各 5 条边界用例通过
7. 同一任务在清单、四象限、详情中的重要性颜色一致
8. 搜索栏常驻，点击进全屏；结果按任务/备忘录/清单分组，返回后滚动位置不丢
9. 删除任务进入回收站，30 天内可恢复；恢复后回到原清单
10. 导航栏中间项可勾选 0–3 个并拖动排序，重启后保持；今天与设置不可移除
11. 首页在任务/专注间切换不丢失列表滚动位置；计时中运行条在任意页可见

---

### M2 · 时间与排期（3 周）

**目标**：让"不会忘"成立，这是生命线。

**范围**

- 提醒：单次/重复，通知按钮（完成/稍后 1 小时），重启恢复
- 权限引导：通知、精确闹钟、OEM 自启动白名单
- 重复规则：RRULE 固定式 + 完成式，例外日
- 日历月/周视图，任务点、逾期红点，长按新建，拖拽改期
- 排程策略：只排未来 N 天，触发后滚动排下一次
- 四象限的紧急度随截止日期变化实时更新

**验收标准**

1. 重启、杀进程、切时区后提醒仍准时（各 3 次）
2. 每日重复只保留未来 7 个闹钟
3. 完成式重复按完成时间顺延，不与固定式混淆
4. 闰年 2/29、每月 31 日、跨夏令时用例通过
5. 日历改期后，列表/四象限/详情同步更新
6. 权限被拒时给出可操作提示，不静默失败

**硬门槛**：真机提醒未实测通过，不许进 M3。

---

### M3 · 专注（2 周）

**范围**

- 番茄（25/5 可调）与正计时
- 前台服务 + 常驻通知（剩余、暂停、结束）
- 结束页：完成 / 补时 / 修正时长
- 时长回写任务"已耗时"，今日专注统计
- 从任务行或详情直接启动
- **全屏专注**：沉浸式、常亮、退出按钮自动淡出
- **横竖屏两套布局**：竖屏单列、横屏双列；跟随系统旋转，全屏内可强制切换
- **两类时间**：剩余时间 + 真实时间 + 预计结束
- **专注中新任务**：底部提示条、半屏浮层、就地完成、可忽略

**验收标准**

1. 锁屏 25 分钟通知误差 < 3 秒
2. 杀进程后恢复或明确提示中断，不静默丢失
3. 修正时长后任务已耗时与统计同步
4. 连续启停 20 次无内存异常
5. 全屏进出 10 次，系统栏与常亮状态正确恢复；返回键只退全屏不结束计时
6. 竖屏/横屏旋转时计时不中断、剩余时间不跳变；横屏最小字号 16 sp、剩余 48 sp
7. 专注开始后新建 3 个任务，提示条 1 秒内出现且显示 3 条；忽略后本次不再提示
8. 真实时间与系统时钟偏差 ≤ 1 秒；跨整分时立即刷新

---

### M4 · 打卡（2 周）

**范围**

- 习惯：名称、图标、颜色、频率（每日/每周 N 次/指定星期）、目标次数
- 一键打卡、补卡（长按日期格）、备注
- 连续天数、本月完成率、月历热力
- 与专注联动（可选）

**验收标准**

1. streak 单测覆盖跨月/跨年/闰年/补卡/跳过/时区（≥20 例）
2. 补卡后 streak 与完成率同时重算
3. 一屏见本周 7 格，打卡响应 < 100 ms
4. 365 天数据渲染不卡

---

### M5 · 备忘录（2 周）

**目标**：让"先收集的资料"有地方去，并能被任务复用。

**范围**

- 备忘录列表（列表 / 卡片两种呈现，四种排序）、编辑页
- 文本（Markdown 子集）、图片（插入/粘贴/拍照，压缩转 WebP）、链接卡片
- 与任务关联：引用 / 快照两种模式
- 任务详情内"备忘录"区块；快速添加时直接新建并关联
- 备忘录转任务
- 全文检索纳入全局搜索
- 备份 zip 含 assets；恢复校验缺失附件

**验收标准**

1. 插入 10 张 5 MB 原图后，备忘录总占用 ≤5 MB（压缩生效）
2. 同一备忘录被 3 个任务引用，改一处三处同步
3. 快照模式修改后与源备忘录互不影响
4. 删除被引用备忘录时提示引用数量，确认后任务不丢
5. 搜索 200 ms 内返回备忘录与任务结果并分组
6. 备份恢复后图片正常显示，缺失时列出清单
7. 列表与卡片切换、排序切换后跨启动保留；置顶始终优先
8. 备忘录重要性色条与任务同色，排序结果正确

---

### M6 · 跨端与捕获（2 周）

**范围**

- Android 小组件：今日清单
- 分享接收（文本/链接→任务；链接可同时存为备忘录）
- 应用快捷方式
- Windows：托盘、`Ctrl+Shift+A`、关闭最小化、MSIX
- ~~大屏并排视图~~ 延后至 V1.1（本阶段聚焦小组件与托盘，避免范围膨胀）
- JSON + assets 全量备份

**验收标准**

1. 小组件 1 小时内刷新，点击直达任务
2. 分享文本 2 步内建任务
3. 托盘关闭后快捷键仍可唤起
4. 小组件与托盘数据一致（并排视图移至 V1.1）
5. 备份→清空→恢复，任务/习惯/专注/备忘录数量与内容一致

---

### M7 · 打磨与发布（1 周）

**范围**：全量回归、性能、空态/错误态、无障碍、上架材料、签名与版本号；外观（主题/字号/配色）、日志查看与导出、关于页（版本/许可/隐私）。

**验收标准**

1. P0 缺陷 0，P1 ≤3 且有规避方案
2. 冷启动 <2 s，列表 60 fps，200 次启动无崩溃
3. release APK ≤25 MB（分 ABI），Windows 包 ≤35 MB
4. 从 V0.x 升级到 V1.0 数据不丢
5. 权限与隐私政策一致
6. 日志能按级别过滤并导出；日志中不含任务标题与备注内容
7. 版本号连点 5 次才出现开发者入口

## 7. 变更控制

1. **范围变更**：新增功能先回答——属于 P0 吗？能延到 V1.1 吗？增加几天？答不清就不做。
2. **技术变更**：新增依赖、改表结构、换抽象 → 必须写 ADR 并记录验证方式。
3. **工期变更**：单阶段超期 30% 时，先砍范围，不延工期。
4. **发布冻结**：M7 开始后只修缺陷，不加功能。
